# PR 描述模板

项目有自己的 PR 模板时用项目模板，确认以下几项都写到了。

```markdown
## 做了什么、为什么
<一两句话；关联 issue：Closes #N>

## 怎么测的
<实际运行的命令和关键输出；界面改动附截图或录像；修 bug 说明测试在旧代码上失败过>

## 风险
风险档：低/中/高。<影响哪些用户或模块；最可能出问题的地方>

## 怎么回滚
<还原这个 PR 即可 / 关掉某开关 / 需要额外的数据回滚步骤>

## 没验证的
<没跑的检查、没覆盖的平台或场景；没有就写“无”>

## 自检
<粘贴自检报告的前几行>
```

写法要求：“测试通过”必须跟着实际命令和数字；没跑的不写成通过；回滚步骤要具体到别人照做就能恢复。
