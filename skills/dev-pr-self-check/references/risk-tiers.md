# 风险分级

先按“这次改动坏了会怎样”定档，再参考文件类型；不按作者资历定档。项目已有分级（gate plan、CODEOWNERS 等）时以项目为准，本页只作缺省。

| 档 | 典型改动 | 合并前需要 |
|---|---|---|
| 低 | 不改行为的文档、注释、测试补充、样式；单个模块内不改对外行为的整理 | 自检报告 + 一位项目负责人或导师过目 |
| 中 | 改了一个模块的对外行为、新增功能、改配置默认值 | 自检报告 + 一位熟悉该模块的人审 |
| 高 | 登录/权限、凭证、计费、CI 与发布脚本、数据库迁移或删除数据、共享核心与公共接口、会被别人照抄的新架构 | PR 标明“高风险”和影响面；代码负责人审，是否要第二人按项目审批规则；能拆就拆小 |

固定要求：

- CI 配置、发布脚本、权限与凭证相关路径，新增、修改、删除都按高风险处理。
- 文档或测试也会升档：改安全操作说明、删掉关键断言或跳过测试、改发布或权限约定，不能因为“只是文档/测试”定低档。
- 实习生自检通过不会放宽人工复核要求；AI 审查通过不算人工批准。
- 审批针对具体提交；批准后又推了新提交，要请人看新增部分。
- 新行为能放在开关后面、先小范围试用的优先这样做，回滚只需关开关。
