# 问卷出口

触发：盘问中某个决定用户自己答不了，知识在另一个人手里（导师、合作者、甲方、另一个团队）。

## 只问"发送"，不问主题
1. 发给谁：对方角色、专长、和用户的关系（决定语气和要补多少背景）。一次问完。
2. 要拿回什么：用户拿到后才能做的决定或事实清单。一次问完。
3. 写问卷：只针对"对方知道而用户需要"的缺口出题；第 2 步列出的每一项都至少有一题覆盖才算完成。

## 落盘
写到项目 TOP/wiki 的既有位置；没有就用项目既有的文档或输出目录，再没有就写 `_outputs/questionnaire-<slug>.md`；不在项目里时按 `rules/artifact-lifecycle.md` 落到 `~/tmp/<date>-<task>/`。报告所选路径。语言跟随收件人。对方答完后把结论写回 spec 或 TOP，问卷本身不当真源。

## 结构

```markdown
# <问卷标题>
**目的**：为什么发、哪个决定取决于它
**来自** <用户>，**发给** <对方>，**答案用途**：<去哪>
## 背景
一段，够对方答题即可。
## 怎么答
截止时间、大概耗时；"不知道"和部分答案都有用，不确定就标出来。
## <主题>
### <单一问题，不复合>
_为什么问_：<只在可能被误读或被敷衍时写一行>
>
## 还有别的吗？
```

题目多于几道才按主题分组；最重要的放前面，因为异步往往只有一轮。
