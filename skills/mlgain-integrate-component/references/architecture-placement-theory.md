# 架构放置的理论判断：这个模块到底该不该接在这

大部分"接错了"不是代码写错，是**理论上这个模块的假设跟你的数据/任务结构对不上**，代码跑起来毫无异常，结果就是不提升甚至变差。动手写代码前，先过一遍这层判断。

## 先搞清楚：这个模块编码了什么"假设"（归纳偏置）

任何一个模块设计出来，都是在替你的模型"预先假设"数据长什么样。这个假设分两种：

- **限制性假设**（模型只能表达符合这个假设的函数）：比如卷积假设"局部性 + 平移**等变**性（translation-equivariance）"——**不是**平移不变性（invariance）：单层卷积的输出会跟着输入一起平移，不是对平移完全无感；"同一个pattern在图像哪个位置都能被同样识别"这个不变性效果，是等变性质**加上**下游的全局池化/聚合（或训练出的近似不变性）才成立，不是卷积层本身单独保证的，写代码/判断适配时不要把两者混为一谈。线性层假设"输入输出是线性关系"。
- **偏好性假设**（模型倾向于但不强制）：比如 Transformer 的 pairwise attention 假设"任意两个位置都可能相关，但要通过数据学出具体权重"，比卷积的假设更宽松。

**核心判断题：这个模块的假设，跟你的数据的真实结构一致吗？**

常见的"假设不匹配"翻车案例：
- 把假设"平移等变性"的卷积模块，接到一个位置本身就有强语义（比如表格里第 3 列固定是某个特定物理量）的特征向量上——"把同一个卷积核滑过去、把不同位置当成同一种模式的不同出现"这个假设在这里不成立（第3列和第4列根本是两种不同的物理量，不是同一个pattern平移出现），模型会被这个假设束缚住，学不到"位置本身就是信息"这件事。
- 把假设"任意位置都能互相看到"的全局注意力模块，接到一个**必须严格因果**的时序预测任务里，却没有加因果 mask——这不是"接错位置"这么简单，是让模型在训练时看到了不该看到的未来（同时也是一种理论错误和数据泄漏，两个问题耦合在一起）。
- 把为"稠密、规则采样"数据设计的模块（比如标准卷积假设规则网格），直接套到"稀疏、不规则采样"的数据上（比如石油领域不同深度、不同频率采样的测井曲线），而不做重采样/插值/专门的稀疏处理——模块本身的假设从一开始就不成立。

## 插入位置本身也是理论判断，不是随便找个地方接上去

- **pre-norm 还是 post-norm 是真实权衡，不是审美**：post-LN 无 warmup 训练不稳，pre-LN 稳但收敛后常略逊——这条不是"选哪个都行"，选之前要知道自己在拿什么换什么。
- **残差路径是"载荷"而非"锦上添花"**：无 skip connection 的纯 attention 按深度**双指数收敛到 rank-1**（这是有理论保证的失败模式，不是偶发 bug）——残差承担的是防止表示坍塌的结构性职责。随手削弱、重缩放或绕过残差，深层网络的表示会退化，不是"这个模块本身没用"。
- **concat 型跳连与 add 型跳连不可互换**：concat 会改变下游 channel 数，误把两者当等价替换是常见的接线错误来源，见 `compatibility-check.md`。
- **模块该放在信息压缩之前还是之后**：如果一个模块设计初衷是"细化局部细节"，接在已经被大幅池化/压缩过的深层特征上，可能已经没有细节可细化了——模块本身没错，位置错了。
- **模块跟现有模块的功能是否冗余或冲突**：比如现有模型已经有一层做了归一化，新模块内部又做了一次同类型归一化，两次操作可能互相抵消或者引入不必要的信息损失。

## 放置有理论依据可循，不是试出来的

具体的"哪类模块该放哪"惯例（含插槽契约、社区维护的默认放置表）见 `framework-placement-conventions.md`——例如 PEFT 的 LoRA 默认放置**不是所有架构统一插 query/value**，而是有一张社区维护的架构→默认插入点查找表，不同架构（尤其用 fused attention 投影的 GPT-2/BLOOM 类）的默认位置并不相同。**核心态度**：遇到不确定该接在哪的情况，先查这个模块所在生态有没有写清楚理由的先例，而不是凭直觉试几个位置挑最好的（那样会掉回 `controlled-comparison.md` 想避免的"多次尝试挑好结果"问题，只是把它从"要不要用这个模块"移到了"插在哪个位置"）。

## 落地动作

写集成代码之前，用一两句话回答清楚：
1. 这个模块的核心假设是什么？（限制性还是偏好性，具体假设了数据的什么结构）
2. 你的数据/任务是否真的符合这个假设？不符合的地方要不要额外处理（重采样、加 mask、改坐标系统……）？
3. 选择接在"这个位置"而不是"那个位置"的理论理由是什么？（不是"论文里就是这么放的"，除非你的任务和论文的任务结构一致）

这三个问题回答不出来，说明还没理解透，不该动手写集成代码——回 `extract-interface-contract.md` 重新把源码和论文读透，或者去查 `feature-and-data-reasonableness.md` 末尾列的高质量参考资料。
