# 受控比较：加一个模块，怎么诚实地判断有没有用

基本规矩不变：**加模块前后，除了声明的这一个自变量，其他所有东西都保持不动**——数据、其他超参数、训练调度、随机种子、评估方式，全部不变。但"其他所有东西保持不动"这句话本身藏着一个大坑：**塞进为旧架构调好的超参下去比，测的是"旧超参有多适合旧架构"，不是消融**。这条单独就能解释一大批"我的模块反而更差"。

## Nuisance 超参必须在两个 arm 内各自重调

把改动分三类：**科学变量**（本次唯一声明要测的东西——是否加这个模块）、**nuisance 超参**（LR、warmup、weight decay、dropout、正则强度——这些必须在两个 arm 内**各自**重新调到最优，不能沿用旧架构调好的值）、**fixed**（其余保持不变的东西，逐条写成结论的 caveat）。

如果新架构因为参数量/结构差异明显不同，需要一套不同的训练配方，先按 `feature-and-data-reasonableness.md` 的方法复现出该配方该有的效果，再启动一轮**同等预算**的独立调参 study——不能拿旧架构调好的超参直接套在新架构上就下结论。

## 三种方差来源（同超参不同 seed 就能造出"统计显著"的差异）

- **trial variance**：同超参不同seed——初始化、shuffle顺序、dropout mask、数据增强的随机抽样、不确定性归约(CUDA非确定性算子)，这些足以造出看似"显著"的差异。
- **study variance**：搜索过程本身的随机性（比如HPO用的采样策略）。
- **data collection variance**：数据切分方式的随机性。

**采纳门 = delta 超出两个arm各自的重训方差带，且收益抵得上新增的复杂度。** 做法：baseline重跑N个seed，得到一个波动带；改动后也重跑N个seed；只有两条分布明显分开才算数。重大pipeline变更后要重新刻画方差，不能沿用旧的方差估计。

## "移除"的操作定义必须先写死

删掉模块？置为identity？保持参数量不变地替换？三种做法结论不同，动手前先声明这次用哪一种，见 `function-preserving-socket-protocol.md` 的S1/S2/S3三层区分。

## 容量匹配对照（区分"这个机制有用"和"这里多了点参数就有用"）

如果要归因到候选模块的**特有机制**（不只是整体改动值不值），应该加一个尽可能匹配参数量/FLOPs的通用MLP/conv对照（`function-preserving-socket-protocol.md` 的S3阶段）——不配平也可以做整体判断，但那样只能回答"整个改动值不值"，不能回答"这个具体机制有没有额外价值"。两个问题不要混着回答。

**这条原则已经用合成实验验证过、也确实踩过反面案例**：第一版实验拿"一个随机线性投影+tanh"当负对照，结果这个"无关"组件也显示出远超噪声带的提升（0.069 vs 3倍噪声带0.045）——排查后发现是这个负对照比 baseline **多套了一层非线性**，容量本身不对齐，不是机制在起作用。改成"同一个 Fourier 特征类、同样参数量，只是 scale 超参数没对上信号频率"这种真正容量匹配的负对照后，结果非常干净：baseline val MSE=0.509，scale 对的那组=0.003（提升约180倍，远超噪声带），scale 错的那组=0.509（跟baseline几乎完全一样，-0.0003，在噪声范围内）。**这次实验本身就是一次真实的"容量不匹配会制造假阳性"案例，不是编的。**

## 不需要管的变化

参数量、训练时间的变化本身不是需要控制的变量。除非模块量级大到训练本身跑不动或者严重欠拟合/过拟合，那属于 `architecture-placement-theory.md` 该处理的架构合理性问题，不是消融方法论问题。但要**记录**这些变化，写进报告的成本delta。

## 违反单变量原则的常见情况

- 加模块的同时顺手调了学习率或换了优化器——见上面"nuisance超参"条款，这不是"违反"，而是必须做的事，只是必须**两个arm都调**，不能只调一边。
- 一次性加好几个"论文里都说有效"的模块——提升了不知道该感谢谁。先把每个模块单独消融过，再考虑组合，组合本身作为一次新的study单独注册（组合有交互，不是加法）。
- 换模块的同时数据预处理也变了——先确认新模块在跟旧模块一样的预处理下也能工作（哪怕效果一般），再谈要不要为它单独调预处理。

## 结构性保障：能被一个 config diff 完整表述

两个arm的差异理想情况下应该能被一个 `_base_` 继承+覆盖一个key的config diff，或一个 surgery policy 完整表达。如果config diff超出了被测组件本身，说明这次比较已经不是单变量——这一点可以用 CI 检查而不用靠人信任。

## 输出空间 delta 先于指标 delta

比较baseline与新模型之前，先看输出空间本身的差异统计（不是只看聚合指标）。**自比较对照**：模型与自身比较，delta必须≈0，否则说明比较管线本身坏了，不是模型的问题。

## 分类别/分桶指标是强制项

聚合数字可能净中性却打坏少数类。分类别/分桶看一遍，不要只信一个全局数字。

## 误差棒披露口径

报告delta时说清楚：误差棒捕获的是哪种变异（切分/初始化/参数抽样/整轮条件）、怎么算的（闭式/库函数/bootstrap）、是std还是SEM、非对称分布不要画对称棒。

## 先验收尺子，再验收改动

花算力跑两个arm之前，先确认你要看的这个指标本身称职——一个非单调或贴地板的指标会在纯噪声周围产生一条权威模样的方差带，这是"先怀疑尺子"原则的可检查形式。四条准入判据，**在看到结果之前**确认，不是之后：
- 沿baseline自己的训练曲线**单调**；
- seed间波动**小于**你希望检出的效应量；
- 在消融尺度上**已经高于随机**；
- 早期与后期checkpoint之间**保序**。

任一不满足就换指标。附带路由规则：**架构改动 → loss曲线可作为可采纳证据；数据/配比改动 → loss曲线不可靠，必须上下游eval验证。**

## 配对 seed 比较（白拿的统计效力）

两个arm跑**同一组seed**（seed=0的baseline对seed=0的candidate，逐对算delta），再看这些配对delta的分布，而不是像"三种方差来源"那节默认的那样比较两个独立抽出的分布。⚠️ 这条溯源是学术的（Bouthillier et al., *Accounting for Variance in ML Benchmarks*），不是实践者共识，跟本文件其余已实验验证的条款置信度不同。

## 环境指纹也是单变量的一部分

"能被一个config diff完整表述"这条不变量要从config diff**扩到env diff**：记录并断言两个arm的环境指纹（torch/CUDA/框架版本+repo commit SHA）。baseline数字若测于不同指纹，比较已经不再是单变量——**baseline必须重跑，不能复用旧数字**。这是最常见的"一次严谨单变量消融悄悄变成双变量"的路径，同一字段要镜像进 `integration-report-template.md`。

## 消融计划的两个字段（吸收自ARIS，给S0期望声明加结构）

写消融计划时，每一行加两个字段而不是自由文本：`what_it_tests`（这次消融具体测的是什么假设）+ `expected_if_component_matters`（如果这个组件真的有用，应该观测到什么）。另加一个显式字段 `unnecessary_ablations`：记下"看着有用但不会带来新洞见、故意不跑"的消融项——给anti-overcaution铁律一个具体的记录载体，证明"少做"是主动决定而不是漏做。

## 阳性对照先于阴性结论

说"模块无用"之前，先证明这条流水线能产出好结果、也能测出好结果：

- 父模型在当前流水线上复现冻结版本的分数（在波动范围内）；复现不了先查流水线。
- 用同一流水线训练一个已知好的模型或官方配方，达到其已知分数。
- 由真值渲染输出（热图/掩膜）再走解码与评价，应满分：证明解码与评价无损。
- 同容量对照与候选同预算、同 seed 配对；对照也要过逐格故障检查。

## 架构改动后的重调与可续跑搜索

两边各自重调干扰超参（学习率先扫旧最优的 0.3×–3×，再 warmup/步数/正则），预算对称，失败与中断计入预算；顺序与工具见 [调参](../../share-autoresearch-engine/references/tuning/README.md) 和 `share-autoresearch-engine/scripts/hpo_study.py`（Optuna SQLite + 心跳重排，默认不剪枝；需要剪枝时只用配对 Wilcoxon 且只用 select 段）。按中间值剪枝会系统性剪掉起步慢的零初始化分支。

## 怎么做（最小流程）

1. 先验收尺子（上方四条准入判据），再有一个干净的baseline分数（多seed刻画方差带）。
2. 声明科学变量、nuisance超参、fixed三类，nuisance在两个arm各自重调。
3. 只加这一个模块，其余按上述三类原则处理，env指纹保持一致。
4. 比较核心指标+输出空间delta+分类别指标，delta超出方差带才算数，否则记`INCONCLUSIVE`。

这条原则的目的是让你自己（以及帮你干活的AI）清楚这次改动到底带来了什么，不是为了防止AI作弊——正规的大模型本身已有不做学术造假的内置准则，这里不需要额外加一层"防作弊"机制。
