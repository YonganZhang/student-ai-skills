# 数据和特征处理是否合理

架构接得再对，喂给它的数据处理方式不对，一样白搭。这部分把 Andrej Karpathy 那篇被广泛引用的 [《A Recipe for Training Neural Networks》](http://karpathy.github.io/2019/04/25/recipe/) 的完整五步法**直接吸收改写成集成新组件时的动作清单**，不是甩个链接了事。核心态度：**神经网络训练是"漏斗抽象"——代码语法完全正确、架构看起来也对，但数据或配置不对时，它不会报错，只会悄悄训得很差**。所以判断"数据处理合不合理"不能靠代码跑没跑通，必须真的去看数据、真的一步步验证。

## Karpathy 五步法，改写成"加一个新组件"的版本

### 第一步：先跟数据融为一体（Become one with the data）

在写任何集成代码之前：

- 真的去翻几百上千条样本，不是只看 `shape` 和 `dtype`。看分布、看有没有异常值、有没有重复/近似重复、类别是否严重不均衡、有没有脏数据。Karpathy 原文强调这一步他会花"以小时为单位"的时间，不是走过场。
- 新加的这个模块期望的输入分布是什么？（比如某些注意力变体假设输入已经过某种归一化、某些频域模块假设输入是稳态信号）你实际喂给它的数据分布跟这个期望一致吗？
- 特征工程本身要能讲出理论道理：这个特征为什么该存在、它假设捕捉的是什么物理/统计规律、跟新模块要处理的信息是不是同一类东西。"因为别的项目/论文这么做"不是理由，除非你确认了那个项目的数据结构假设跟你的一致。

### 第二步：搭一个端到端的骨架 + 拿到一个"笨"baseline（End-to-end skeleton + dumb baselines）

- 先固定住整条 pipeline（数据加载→模型→loss→评估）跑通一遍最简单的版本，得到一个基线数字，哪怕这个基线很笨（比如时序预测直接用"明天=今天"、分类直接猜多数类）。
- 加新组件之前，确认这条骨架本身没问题：input-independent baseline（比如把输入全部置零，看 loss 是不是应该退化到某个可预测的值）、可视化刚好在网络输入端的数据（真的看一眼喂进网络的最后一刻数据长什么样，不是只信任 dataloader 代码逻辑）。

### 第三步：过拟合（Overfit）

- 用一个极小的子集（甚至一个 batch）让加了新组件的模型过拟合，确认**至少还能正常学习**（loss 能降到接近 0）。如果连过拟合一个小 batch 都做不到，说明模块接线或数据处理有硬伤，不用往下跑完整训练去"看效果"，先在这一步就能发现问题——这是最快、最便宜的排错手段。

### 第四步：正则化（Regularize）

- 过拟合验证通过之后，再考虑加回数据增强、正则化手段、更大的数据集。这些手段应该逐个加，不要在还没确认组件本身能正常学习之前就一次性堆上去。

### 第五步：调参、榨干最后的性能（Tune / squeeze out the juice）

- 到这一步才轮到常规的超参搜索。**注意顺序**：组件放对了位置、数据处理确认合理、过拟合验证通过、正则化调好——这些都做完之后再调参才有意义；反过来，在架构本身可能有问题的阶段就大量调参，是在浪费算力掩盖一个本该在更早阶段发现的问题。

## 增量验证的核心逻辑

从小容量、简单配置开始，一步步加复杂度（先跑通最简配置，再加新模块，再加正则化，再调参），而不是一次性把新模块、新的数据增强、新的正则化手段全部一起加上——这样出问题也分不清是谁的锅。这跟 `controlled-comparison.md` 讲的"一次只改一个变量"是同一个逻辑，只是应用在"从零搭建/调试"这个阶段。

## 两个验证集：把 distribution shift 从 variance 里分离出来

只有一个验证集时，"训练集好、验证集不好"这个观测无法回答"是欠拟合/过拟合，还是验证集本身跟训练分布不一样"。同时持有**训练分布验证集**（跟训练数据同分布的留出集）和**测试分布验证集**（尽量贴近真实部署场景的数据），把
`test error = irreducible + bias + variance + distribution shift + validation overfitting`
拆开，先测哪一项在动，再决定往哪个方向改：欠拟合分支走"加容量→减正则→误差分析→换架构→调参→加特征"；过拟合分支走"加数据→归一化/增强/正则→调参→换架构→误差分析→早停/减小规模"。

## 验证集结构是假阴性的上游原因

验证分数骗人，经常不是模型的问题，是切分方式的问题：**时序数据要取连续最新块**而不是随机切分（随机切分会让模型"背"到未来信息）；**分组数据**（同一人/同一口井/同一会话产生的多行）必须按组切，否则验证分数在测量记忆而不是泛化。这两条在 `compatibility-check.md` 里也会作为构造期检查项出现。

## 迷路时的重置程序（有序、可终止）

集成之后彻底看不出问题出在哪时，按这个顺序退回去，而不是随便改一个地方赌运气：

1. 退回一个简单的、已验证过的模型 + 标准 loss。
2. **关掉全部正则化与数据增强**——这一步直接对治"新模块的收益被为旧架构调好的正则化掩盖"这个常见假阴性来源。
3. 微调场景下核对预处理与原模型完全一致。
4. 核对输入数据本身的正确性（回到第一步"跟数据融为一体"）。
5. 在 2-20 个样本上过拟合，确认这条链路本身能学。按训练时用的变换评估（没用翻转训练就不要用多方向平均评分），用任务指标判断；软目标的损失有下限，不按"loss 减半"判断。
6. 逐个重新加回组件：增强 → 正则 → 自定义loss → 复杂模块。每加回一个都单独看一次效果，不要一次全加回去。

## 输入端叠图、反向对照与增强同步

"看一眼数据"要落成可重复的检查，并证明检查本身看得见错误：

- **叠图**：从真实 dataloader（含增强与裁剪）取若干批，把标签画在实际喂进网络的张量上，存 PNG，人看一眼。
- **反向对照**：同一统计在"错误版本"上必须消失。点标签：标签处亮度/响应减全图均值应显著为正，行列互换后应接近 0；掩膜：内外差 vs 翻转掩膜后的内外差；分类：打乱标签后训练应退化到随机。反向对照不消失，说明检查看不见标签或标签本身有问题。
- **增强同步**：合成已知点/掩膜走同一套几何增强，变换后的标签与图像极值的距离中位数 < 0.5 像素；测试里保留"只变换图像"的反例，确认它会报错。
- **约定写成断言**：(row, col) 还是 (x, y)、像素中心是否有 0.5 偏移、网络输入与原图的尺度换算、归一化统计量来源（逐窗口 vs 整图）。

实现：`scripts/alignment_probe.py`。1号点检测案例中，标签处信号 0.27、行列互换后 0.006，增强同步中位误差 0.39 像素。

## ⚠️ 环境层面的"训练异常慢"陷阱（实测踩过）

跑本skill的合成实验时真实遇到过：在一台 192 核的机器上，PyTorch 默认线程数会顶到核数量级，结果一个几层的小 MLP 训练进程吃到 8000%+ CPU、几百分钟的 CPU 时间，墙钟时间却只有几分钟——纯线程调度开销，不是真的在算。**这不是理论提醒，是这次真实发生过的事**。核数很多的共享机器上跑小模型，先 `torch.set_num_threads(4)`（或类似的小数字）再开训练；如果有空闲 GPU，小模型也优先扔上去，比在几十上百核的CPU上跑更快也更不容易占用共享资源。这属于 Karpathy 说的"训练是漏斗抽象"的一种具体表现——症状是"训练慢得不正常"，跟模型/数据都无关，根因是环境配置。

## 落地动作

- [ ] 真的看过数据样本，不是只看统计摘要。
- [ ] 有一个跑通的端到端骨架 + 一个笨 baseline 数字。
- [ ] 新模块期望的输入分布，和你实际喂给它的数据分布，写清楚是否一致。
- [ ] 每个新增/改动的特征，能用一两句话说清楚"为什么它对这个模块有意义"。
- [ ] 先过拟合一个小子集验证模型能学，再跑完整训练，再正则化，最后才调参。

## 值得直接查阅的现成高质量资料

社区里没有一个"装上就能自动判断架构对不对"的现成工具或 skill（这次专门为此又做了一轮 GitHub 搜索并逐条翻查了几个"Agent Skills 大全"仓库，确认没有），但有三份公认高质量、免费、随时能查的参考资料，比凭训练记忆判断可靠得多：

- **[Karpathy: A Recipe for Training Neural Networks](http://karpathy.github.io/2019/04/25/recipe/)** —— 上面这套五步法的原文，遇到"训练但不报错、就是学不好"的情况，直接去查这篇文章对应的排查步骤，写得比这里详细。
- **[labmlai/annotated_deep_learning_paper_implementations](https://github.com/labmlai/annotated_deep_learning_paper_implementations)**（也叫 nn.labml.ai）—— 60+ 篇经典论文（各种 Transformer 变体、优化器、GAN、扩散模型、GNN、强化学习算法）的逐行注释实现。用法：先确定你要集成的组件属于哪个家族（比如"这是个门控机制"→查它家的 GRU/Highway Network 实现；"这是个位置编码变体"→查 RoPE/ALiBi 的实现），直接对照着看它在真实代码里到底放在哪一行、前后接的是什么，比凭印象猜可靠。
- **[d2l.ai (Dive into Deep Learning)](https://github.com/d2l-ai/d2l-en)** —— 被 500+ 所大学（含斯坦福、MIT、剑桥）采用的交互式深度学习教材，同时给数学推导、代码实现和直觉解释，覆盖 CNN/RNN/Transformer/注意力机制等主流架构家族的原理章节。当你需要搞清楚"这类模块的数学原理到底是什么、为什么它会有这种归纳偏置"时，比零散的论文或博客更系统。
