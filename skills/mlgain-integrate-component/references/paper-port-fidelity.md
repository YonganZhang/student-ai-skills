# 论文模块移植：先证明实现忠实、接入正确

条件：把论文或作者仓库里的模块/损失/训练技巧移植进本项目的模型。
不变量：下列检查没完成前，不能用"这个模块不适合我们的数据"解释失败。
来源：DeepCode 的论文抽取与计划模板、AREX-Skill 的论文结果复现流程、RD-Agent 的移植等价评估（各自卡片见 `~/.claude/skills/share-autoresearch-engine/references/upstream/`）。

## 1. 抽取：每个超参都要有出处

为每个组件写一张卡：公式或伪代码（标注节号/公式号/表号/页码）、输入输出张量与轴含义、归一化/激活/残差位置/初始化/参数共享、配套训练策略（学习率、warmup、损失权重、增强）、超参取值及出处。单列"论文没写但必须有"的项（例如 padding、epsilon、初始化方差、门控初值），并写明本地取值依据。没有出处的值不能当作"论文设定"。

## 2. 对应表（交付物）

| 论文公式 / 作者代码 | 本地实现（文件:符号） | 接口适配 | 实质改动 | 验证证据 |
|---|---|---|---|---|

- 接口适配：张量排列、通道数、2D/3D、batch 维度、数据类型。
- 实质改动：换归一化、改残差路径、2D 改 3D、删分支等——这类必须标为"适配版本"，结论只对适配版本成立。
- 覆盖门：计划里的每个公式/组件都要对应到代码符号与一条测试；缺一个就记"移植未完成"，不记"完成"（DeepCode 的计划文件覆盖检查推广而来）。

## 3. 等价测试（能拿到作者实现时）

- 同一份 `state_dict` 复制到作者实现与本地实现，同输入、同 eval 模式，比较输出；必要时比较对应梯度。容差按 dtype 设（fp32 约 1e-6 量级），记录最大绝对/相对误差与覆盖的形状。不用"平均误差 < 0.1"这类宽松阈值（RD-Agent 原评估器的阈值区分不开实现错误）。
- 覆盖多个形状（含奇数尺寸、batch=1）、train 与 eval 两种模式（BN/dropout 行为不同）。
- 拿不到作者实现时：写明证据缺口；用公式在小输入上独立计算对照（手算或另一独立实现），不写"与原作者一致"。

## 4. 接入检查（与组件工作流共用）

- 模块确实进入 forward 与 loss 路径；配置开关真的到达构造点（训练进程内部打印解析后的配置）。
- 优化器参数组引用当前模型的参数对象，无漏、无重、无旧对象；解冻后重新检查（`../scripts/train_sanity_checks.py`）。
- 真实训练步中参数按设计更新；零初始化/门控分支几步后解锁，且不是"门控与最后一层同时为零"（`../scripts/module_probe.py`）。
- 冻结层、条件分支、预训练权重加载（strict，列出不匹配的键）、检查点重载后输出一致。
- 关闭候选改动时，在相同基线权重和受控随机条件下逐位恢复基线行为。

## 5. 复现计划（动手前写好，五节）

文件结构、组件实现顺序、验证方案（上面第 3、4 节的具体命令）、环境与依赖、实施策略（先最小可运行，再完整训练）。缩减版（少步数、少数据）与完整训练分开记录；结果 JSON 由脚本生成，不手写；声称"训练过"就要证明参数前后不同。AREX 的论文结果复现流程原文见 `~/.claude/skills/share-autoresearch-engine/references/upstream/vendor/arex-recover-paper-result.md`。

## 6. 之后才比较

通过以上检查后，按[受控比较](controlled-comparison.md)与同容量对照判断收益；结果反直觉时按[排错](../../share-autoresearch-engine/references/triage/README.md)逐层排查。
