# 图片工具与提供方选择

这是图片 PPT 和科研插画的提供方选择真源；精确数据图应用代码绘制（科研绘图技能 `share-sci-plot`（可选，本包未包含））。

| 用户意图 | 图片生产入口 |
|---|---|
| 未指定提供方 | 宿主官方 `image_gen` / `image_generation`；模型可选时用 ChatGPT Image 2（GPT Image 2） |
| 点名 Nano Banana 2 / Nano Banana / Gemini 生图 | Google 官方 Gemini / Antigravity 生图（调用方式属外援技能，本包未包含）；沿用同一内容、版式和交付合同 |

- 工具无模型参数或未返回模型 ID 时，记录实际工具来源与尺寸，不凭效果声称已核实型号或原生 4K。主推理模型与图片模型分别记录。
- 默认工具缺失或所选工具失败时保留进度、报告缺口；用户已有提供方授权则依授权继续，否则不自动换后端。
- 宿主工具、Google 会员、FAL/API 是不同额度路线；不承诺无限生成，不读取凭证拼订阅 HTTP，不自动购买 credits 或切第三方付费接口。
- 旧 FAL 与 `codex-image` 入口均拒绝执行，不提供缺工具时的备用路线；历史资料见 [入口](../SKILL.md)（旧 Codex 脚本归档未随本包发布）。

## 跨宿主能力核验

技能提供做法，不会自动安装图片工具。Codex、Claude、DeepSeek/DSH 都先检查当前会话实际暴露的工具：`image_gen` / `image_generation` 等图片生产能力才可执行默认路线；`read_image`、终端、PptxGenJS、HTML截图和技能 `skill` 加载器均不能替代。

当前工具清单没有图片生成能力、也没有用户已选择的其他后端时，能力核验到此结束。已安装某个 CLI、持有订阅或能读到旧脚本均不代表可生图，不继续遍历其他模型 CLI、认证配置或历史脚本寻找替代入口。

缺少所选图片工具时，继续整理能完成的逐页内容、完整提示词、白底与密度要求、参考素材和备注，并记录到项目输出目录；向用户说明“尚未生成图片”，给出实际可用的下一步。已有授权且目标会话确实有图片工具时，交接给该会话（跨窗口协作技能本包未包含，可由用户手动转交）；否则说明需要具备该能力的会话或用户选择其他已支持后端。不要把任意 Codex CLI 窗口视为一定有生图工具，也不自动调用外援、切付费接口或交付代码绘制整页冒充生图。

## Codex code-mode 图片回收

按当前图片工具的返回结构处理。`image_gen__imagegen` 返回 `{image_url, output_hint}` 时，在同一 exec 中调用 `generatedImage(result)`；需要跨 exec 使用时先 `store` 保存结果。不要按 MCP 的 `result.content` 结构读取，也不要把完整 base64 打进文字日志。

查看工具给出的文件路径或 `output_hint`，核对图片内容后复制原始文件进项目。若工具调用已成功但当前变量丢失，先检查本次会话的生成目录（通常是当前 `CODEX_HOME/generated_images/<session-id>/`）；用调用时间、会话和实际画面确认归属，不能拿其他任务的图代替。确认没有可恢复产物后才报告缺失，是否重新生成仍服从本次授权次数。
