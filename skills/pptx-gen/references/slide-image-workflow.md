# 完整图片PPT工作流

## 科研单图入口

新 SCI 图一、论文方法架构、机制插画、图形摘要，如已安装 `share-sci-plot`（可选，本包未包含），先读其科研示意图候选合同。按合同独立设计并用选定的官方图片工具生成实际候选，交付选择或按用户指名优点融合；数量、排除项、完整交付授权与后续处理均以合同为准。

这类单图按论文版面确定尺寸、比例、文字与字体，不继承幻灯片标题、16:9、背景—Gap—研究目标栏目及演讲备注。精确计算关系走 `share-technical-roadmap` 的可编辑节点；本流程生成的图片不称可编辑图。以下逐页流程适用于完整图片PPT，不要求每页生成三套。

## 生成前

生成或重绘时读取 [设计手册](slide-design-manual.md)，落实入口中的白底、内容密度与交付形式；按 [图片后端](image-backend-alternatives.md)确认当前会话具备所选生图能力。用户只要求已有图片原样装册时直接走备注与组装，保留原图风格，不要求生图工具。

1. 确定交付形式。用户说把图片放进PPT时，制作图片PPTX并写演讲备注；明确只要图片时交PNG。只有明确要求可编辑重建时才增加重建页。
2. 从论文、代码与实际结果核对内容，确定主线、逐页问题、上屏文字、图示关系和前后承接。
3. 对用户逐页反馈建立修改映射。问题页需要重做，不只在备注里解释，也不只新增几页。
4. 每页提示词包含完整准确文字、布局、颜色、内容图与风格图的角色。科研目标与内容应有明确小标题及完整句子。把[真实图边界](slide-design-manual.md#参考与真实图)写入提示词：未给实验数据时画流程、关系或核验步骤，不补造结果图、来源或占位字段。
5. 将入口确定的背景（默认纯白 `#FFFFFF`）、16:9、完整文字和内容密度写入每页提示词，风格参考不得改变这些条件；希望的清晰度与实际返回尺寸分别记录。

## 生成

- 按 [图片后端](image-backend-alternatives.md) 选择工具：默认宿主官方图片工具，模型可选时用 GPT Image 2；显式 Nano Banana 2 使用 Google 会员路线。
- 每个独立页面单独调用。批量任务仍用已选定的官方图片工具；不要因为批量而改走付费API。
- 参考图先看图；内容参考保留数据与关系，风格参考只借用画风，不能复制上一页文字。
- 每页直接生成含全部文字、图示与版式的完整图片，不生成空白背景后用代码叠字。
- 输出保留在宿主生成目录后复制进项目`_outputs/pptx-gen/<task>/slides/`；记录本页提示词与实际工具信息。
- 发现错字、缺句、错误箭头或虚构角色时，用同一选定工具修正，重新检查。

## 备注与组装

- 备注写成自然口述：本页要讲什么、图怎么读、必要技术解释、比较条件和下一页过渡。不要仅复制页面文字。
- 页面由完整图片装入16:9 PPT；`scripts/images_to_pptx.py`接受按顺序编号的PNG和含`pages`数组的JSON，各项含`n`、`question`、`notes`。
- 执行 `python scripts/images_to_pptx.py <images_dir> <content.json> <out.pptx>`；需要python-pptx，按项目环境安装，不全局装包。
- 组装不等于可编辑重建。幻灯片图片保持完整，备注是可编辑文字。

## 验收与交付

组装前逐页查看实际生成或重绘的图片：背景是否符合要求，正文是否含必要事实与解释，标题、专业内容、数字与箭头是否完整正确，是否残留占位符或无来源的结果比较；精确图必须与来源一致。定性示意须在图中明确，备注不能消除画面上的误导。没有明确改背景的授权时，新生图的黑底或深色全页先用图片工具重做；信息太空的页先补内容再生成，不能靠备注补齐上屏内容。只检查提示词、文件存在或图片尺寸不算视觉验收。原图装册只检查忠实装入与显示，不据默认风格擅自修改用户原图。
检查页数、页序、图片实际尺寸和16:9比例，验证每页图片及备注与输入一一对应。组装脚本只验证结构与图片/备注对应，不判断美观、白底或生图来源；HTML截图也是PNG，文件格式不能证明调用过图片工具。
用PowerPoint读取库重新打开PPTX，检查图片对象和备注；有渲染器时渲染全册，无渲染器时明确验证限制，整页图片可直接检查图片画面。
正式交付PPTX下载链接，按需附总览。只要PNG时用`package_slide_images.py`检查纯PNG ZIP；需要4K时显式加`--require-4k`，按真实尺寸验收；不要放大图片后冒充原生4K。
工具失败时保留已完成页和提示词，报告当前能力缺口，不把内容文档称为完整PPT。达到本次生成次数上限仍有画面缺陷时，保留失败样本并列为未完成项；装册成功不改变质量未通过的结论。
