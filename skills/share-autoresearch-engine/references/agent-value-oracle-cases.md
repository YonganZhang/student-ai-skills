# Agent 价值验证 SOP：适用性与反例

本文用于设计审查和手算/小规模自动测试，不提供通用最优化实现。

## 代表性路由

| 请求 | 预期处理 |
|---|---|
| “Agent 增益很小；全选对能提高多少？” | 先固定动作/预算，测受限oracle，再决定训练 |
| “有标签，倒推每个区域该保持还是纠错” | 原生联合评分，产出动作价值/可接受动作标签 |
| “给模型路由器做训练数据” | 冻结候选模型，包含成本和不动作；区分候选缺失与选错 |
| “检索总能选对文档，回答能提高多少？” | 重跑冻结下游回答/验证；检索命中不是最终成功 |
| “规划Agent为何没提升，是否改提示词？” | 先检查可执行序列、终局收益和部署可观察信息 |
| “先讨论值不值得做成Skill” | 讨论方法与边界，不自动启动模型训练 |
| “修ImportError/接口shape异常” | 普通调试，不强制oracle实验 |
| “把纯展示网页改成蓝色” | 普通实现，不触发科研价值验证 |
| “没有标签、模拟器或可靠验证器，给精确上限” | 说明无法直接建立精确oracle；提供有限可验证子任务，不编造标签 |

以上为人工语义验收预期，不等于真实模型已经自动触发该路由。

## 可计算的反例

1. 模型选择：三个样本的候选正确性为[[1,0],[0,1],[0,0]]。固定第一模型1/3，逐样本理想选择2/3，候选全错的最后一个样本不可凭选择器修复。这个简单可加例可以精确枚举。
2. 成本：若第二样本改用第二模型的额外成本抵消所得收益，则有精度潜力但没有净效用改善；预算不应被oracle豁免。
3. 交互：两处修改都不做=0，只做任一处=1，同时做两处=−1。逐域独立“都该改”合成后更差；精确联合最优是1，不是局部相加的2。
4. 隐藏信息：相同可见输入下，正确动作由独立公平隐藏位决定。看标签的理想选择100%，任何无额外信息的策略期望50%。大oracle gap不等于训练一定能闭合。
5. 序列：第一步拿即时1分后只能终止；另一动作即时0分但下一步可得3分。只看即时收益会选错；需要在同预算下比较终局。
6. 近似搜索：一个动作组合值10，贪心只找到1；1是已找到的可行下界，不能用它宣称上限很低而停掉设计。
7. 原子纠错项目：候选“保留q/采用冻结p”与“按真值重画/任意补删移”是不同动作空间。尚未运行精确联合oracle时，只能说有标签可构造该实验，不能宣称已经测出其上限。
8. 工具和代码修复：测试通过/工具调用成功不必等价于任务完成；测试不完备时应限定评价结论，不能把验证器漏洞当收益。

跨项目部署前，用该项目实际动作和评价器替换上述玩具定义，至少验证OFF自比较、合法动作、预算约束、非可加评价及训练/留出用途。
