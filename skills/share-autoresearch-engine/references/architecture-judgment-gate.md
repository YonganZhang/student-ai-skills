# 结构判断门禁：先决定改哪里，再决定加什么

适用：任何要加模块、换 backbone / neck / head、改 skip / 残差 / 融合方式、或移植论文结构的**正式**深度学习实验。

不触发：只调学习率、seed、预算、数据增强，或只做推理/结果汇总，不改前向结构或接口。
不变量：**正式结构实验没有判断单，不进入优化器更新；有界接线探针不升级为结构证据；没有能区分假设的对照，不把负结果归因于模块。**

## 为什么必须前置

模块效果不是一个孤立属性，而是：

```text
模块机制 × 放置位置 × 接口契约 × 数据与训练配方
```

固定同一个接口换十个模块，只检验了一个放置假设；它不能回答“这个模块有没有用”，只能回答“这个模块在这个位置、这个接口上有没有用”。

## 正式实验的启动条件

在提出具体结构方案之前，先在实验记录里写下 **结构判断单**；正式训练命令之前必须已存在并绑定当前配置。缺关键项，不进入正式结构实验。
未写单时允许：只读阅读、shape/接口推演、无参数更新的静态检查，以及**已授权的固定少量 step 接线探针**；探针必须标 `probe`、不进结果表、不作为模块有效/无效证据。

正式结构实验的训练入口若已有 gate，应在首个 `optimizer.step()` 之前校验：判断单路径存在、六项非空、预填配置哈希与本次一致；缺失/过期非零退出。判断单路径、卡哈希与配置哈希写入 run 目录的 `structure_gate.json`，卡原文快照为 `structure_card.json`。项目没有这个入口时，至少把判断单绑进实验记录并人工复核，不要求所有项目先造 gate。

1. **失败模式**：当前模型的错误主要是 FP、FN、定位偏差、尺度失配、域偏移、阈值迁移，还是训练不足？给出证据，不写“感觉”。
2. **结构地图**：目标模型的实际前向图；标出 encoder / bottleneck / decoder / skip / neck / head，以及每处张量的通道、分辨率、stride、归一化。
3. **机制假设**：这个改动为什么能改变上面的失败模式？它引入的是新信息、新归纳偏置、新优化路径，还是只增加容量？
4. **位置候选**：候选位置按结构决定，其中一个是论文/原结构的原生位置；新模块没有论文位置时，写“无外部原生定义”，把机制上最接近的层当作本地参照并写依据，不虚构论文出处。只有一个合理位置时写明原因。
5. **单轴实验**：这一轮只动“位置”或只动“模块”，不同时动 loss、数据、训练配方；写明 baseline、预算、seed、主指标和成功阈值。
6. **证伪条件**：什么结果算失败？同一接口连续负结果时，先审查接口和搜索空间，不直接外推“模块家族无效”。

**短版合同**：局部小改可以用六项各一句的短版，可引用未变的结构图/接口契约；但六项都必须在，失败证据、位置、机制、证伪不能省。结构、接口、数据或训练配方变化后，旧判断单失效，必须重写受影响项。

## 机器可读判断单

人工模板在上；训练入口使用 JSON 版本，覆盖同一组字段：

- 模板：[structure-card.template.json](../assets/structure-card.template.json)
- 校验（从 skill 根目录）：`python3 scripts/structure_gate.py check --card CARD.json --config CONFIG.json`
- 配置哈希：`python3 scripts/structure_gate.py hash --config CONFIG.json`
- `config_sha256` 可留空，由训练入口把结构配置哈希写入 run 目录的 `structure_gate.json`；卡原文同时快照为 `structure_card.json`；也可预填，预填不一致直接拒绝。
- Lightning 模板只把 `model` / `module_type` / `structure` 写成 `structure_config.yaml` 再哈希；lr/seed/budget 和续跑标记不会改变结构绑定。选点口径（loss、loss_weights、tasks、`data.target_dtypes`）另写 `selection_recipe.json`，同一 run 改变它会被拒绝。要复算结构哈希就对这个文件跑 `hash --config`，不要拿完整 resolved config 代替。
- 单轴预算与 seed 必须覆盖本次运行；`budget_steps` 或 `seeds` 不匹配即拒绝。

脚本只证明六项存在、格式完整、卡与配置一致，不判断机制是否成立。正式实验的训练入口应把 `--structure-card` 接到优化器创建之前；缺卡、卡过期、预算/seed 不符都在首次参数更新前退出。项目入口不支持时，至少保存卡与配置哈希并人工复核，不能只靠独立跑一次 `structure_gate.py check` 冒充已绑定：

```bash
python3 -m pipeline.train --config CONFIG.yaml --structure-card CARD.json --validate-only
```

只有 `status=structure_gate_ok` 后，才去掉 `--validate-only` 开训。参考模板的示例 config 用 `structure.mode: baseline` + `baseline_reason` + `baseline_sha256` 声明无结构改动；`baseline_sha256` 是 `model + module type` 的指纹（不含 lr/seed），改了模型却保留旧指纹会被拒绝；它防误标，不防蓄意重算，蓄意改结构仍必须走 changed + 卡。改模型/head/位置必须改成 `changed` 并给卡。

## 位置优先于模块

正确顺序：

```text
先固定一个模块
  → 在原生位置、bottleneck、decoder、neck 等位置做位置消融
  → 找到有响应位置
  → 再比较模块族
```

错误顺序：

```text
先固定一个外挂接口
  → 换十个模块
  → 全部不涨
  → 得出“模块都没用”
```

第二种顺序的负结果是**相关的**，不是十次独立失败。

## 原生接口优先

“原生”至少包括：

- 论文中的插入层级与前后算子；
- 输入输出张量的语义、通道、分辨率、stride；
- 归一化、激活、初始化、残差/门控位置；
- 配套训练配方（学习率、warmup、loss 权重、增强）。

只满足 shape 能跑通，不叫原生接入。若为了本地模型做了实质改动，标记为 **适配版本**；结论只对适配版本成立，不能写成“论文模块无效”。

## 最小实验矩阵

矩阵分两关，第一关必须：

**第一关（必须）**：位置消融。不是三选一，不能用模块/机制消融代替。

| 实验 | 固定 | 变化 | 回答 |
|---|---|---|---|
| 位置消融 | 同一模块、同一预算 | 能区分假设的候选位置 / 原生 vs 外挂 | 是不是放错了；单位置须写明原因 |

**第二关（位置结果取得后）**：再选模块或机制矩阵。

| 实验 | 固定 | 变化 | 回答 |
|---|---|---|---|
| 模块消融 | 同一已验证位置、同一预算 | 多个候选模块 | 是不是模块不对 |
| 机制消融 | 同一位置与模块 | 开/关、随机初始化、容量对照 | 收益是否来自声称的机制 |

只做第二关、没有位置结果，不能自称完成结构判断；结论只能写成“该位置上的模块比较”。
若位置实验没有任何位置响应，停止比较模块族，先检查结构图、接口与训练配方，不要继续换模块。

## 结论边界

- 负结果只覆盖：**这个模块 × 这个位置 × 这个接口 × 这份数据与预算**。
- 没做位置对照，不得写“该模块不适合本任务”。
- 没做原生接入，不得写“论文方法无效”。
- 没做机制对照，不得写“提升来自预训练/注意力/新模块”。
- 分支有输出但排名不变，只能写“接线成功、未影响选择”，不能写“有效”。

## 反模式

- 只换模块，不换位置；
- 把“残差安全”当成“残差有效”；
- 看到 CCF A 模块就默认能迁移；
- 只加容量，不对应任何失败模式；
- 先用 1×1 外挂融合，再解释为什么没涨；
- 连续负结果后继续换模块，不复盘搜索空间。

## 审查清单

- [ ] 失败模式有证据，不是猜测
- [ ] 结构图画到张量级
- [ ] 候选位置含原生位置；单位置已写明原因
- [ ] 本轮只动一个轴

- [ ] 成功阈值与证伪条件预先写定
