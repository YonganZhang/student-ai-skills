# Auto Research：有边界的自动实验循环

“Auto research”不是让 agent 无限试错。它是**有预算、有基线、有门禁、可审计**的闭环。没有门禁的自动搜索，只会更快地过拟合验证集。

## 输入

开始前必须有：

- 任务与部署单元；
- 主指标、辅助指标、阈值规则；
- 数据路径与只读边界；
- fit/select/evaluate 划分；
- baseline 及其预算；
- 最大预算、并发上限、停止条件；
- 允许改动的范围（数据/模型/损失/训练/后处理）。

缺一项，不启动自动搜索。

## 与 S1–S9 的关系

阶段定义只维护在 [标准流程](workflow/standard-flow.md)。本文件不复制阶段表，只规定**自动循环额外必须满足的边界和产物**；首次选栈或实质换栈先做 [S0 stack card](../assets/stack-card.template.md)。

自动循环每一轮至少记录：

- 假设、最小 diff、没改什么；
- 配置、seed、数据版本、预算、停止原因；
- 曲线审计（best step、`BEST_AT_CAP`、是否右删失）；
- 与同口径 baseline 的比较，而不是与历史偶然高分比较；
- 结论等级：`supported` / `inconclusive` / `contradicted`。

## 角色分工

- **Planner**：写 stack card、预算、停止条件；不改代码。
- **Implementer**：只在允许范围内改；每次改动写清假设。
- **Auditor**：独立检查数据/指标/划分/选点；不共享 implementer 的结论。
- **Analyst**：只读冻结结果；先看曲线和方差，再看均值。
- **Human**：开 test、跨领域、大预算、对外主张。

角色可以由同一模型分阶段扮演，但**不能自己改、自己审、自己宣布通过**。

## 停止条件

立即停：

- 没有 baseline；
- 选择指标与报告指标不一致，且没有定义好的关系；
- best step 落在预算上限且预算无法扩展；若已明确固定预算，只标右删失，不把该比较判死；
- 验证集已用于过多试验，且没有新的 held-out；
- 需要开 test 才能决定下一步；
- 两个候选差异小于方差地板；
- 改动越过允许范围；
- 数据泄漏/评测器错误。

## 输出

每次实验必须写：

- 假设；
- 改了什么（最小 diff）；
- 没改什么；
- 预算与停止原因；
- 曲线审计；
- 多 seed 结果；
- 结论等级：`supported` / `inconclusive` / `contradicted`；
- 下一步，或“停止”。

## 反模式

- 用 test 调参；
- 只报最好 seed；
- best 在 cap 上仍宣布收敛；
- 一次改多个模块，无法归因；
- 没有 baseline 就宣布 SOTA；
- 用“公平性不重要”掩盖不等预算；
- 自动搜索无 trial 上限；
- 把“没跑出”写成“没用”。

## 统计与选点

统计方法、模块放置、消融设计和选点卫生仍走标准流程及 [Selection Hygiene](selection-hygiene.md)；本文件只规定自动循环的边界与产物。
