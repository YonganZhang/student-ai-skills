# 地学融合设计案例约定

仅用于已有地学项目的领域语义与历史设计参考；通用融合和最小实验合同以[融合入口](../multimodal-fusion-design.md)及[端到端 SOP](../end-to-end-learning-sop.md)为准。下述全矩阵/查询局部性要求只在相应任务中适用，不要求每次模块试验先训练所有父模型。


这份参考用于“改进已有冠军”而不是凭模块名字拼大模型。目标是把一次创新写成可证伪的设计假设，并在张量、语义、数据边界和预算四个层面证明它能公平比较。

## 1. 先诊断，再组合

候选必须按以下因果链产生：

`可复现失败 → 机制假设 → 1–2 个主要改动 → 预期改善的指标/样本组 → 反证实验`

没有对应失败证据的模块不进入候选池。参数更多、论文更新或名字更复杂都不是设计理由。若一次引入两个主要改动，必须同时登记 A-only、B-only、A+B；预算不足时只做一个改动。

## 2. 六类设计原语

| 原语族 | 可以改变什么 | 常见地学目的 | 必须保留的对照 |
|---|---|---|---|
| representation | 归一化、窗口、频率/尺度、坐标、token 粒度 | 让表征与深度、时间、层位或空间尺度对齐 | 原表征 + 同一后端 |
| encoder_architecture | CNN、Transformer、图网络、神经算子、树模型 | 改变局部/全局感受野或归纳偏置 | 参数/更新预算相近的强骨干 |
| fusion | early/late、门控、交叉注意力、残差、query-local | 合并地震、测井、轨迹、地质统计或基础模型特征 | 单模态父模型、random/frozen 控制 |
| loss_objective | 类别重权、边界、连续性、排序、物理/结构正则 | 对齐不平衡、断层边缘、层序或守恒目标 | 原损失；逐项去除正则 |
| geological_prior | 层位、断层屏障、各向异性、井约束、变差函数 | 限制不合理跨层/跨断层传播 | 打乱先验、欧氏先验或无先验 |
| training_strategy | 预训练、冻结/解冻、课程、增强、采样、校准 | 提高小样本稳定性或缺模态鲁棒性 | random-init、等更新数、等数据量 |

一次候选最多选择两个原语族。若改动跨越三个以上原语族，它属于新架构研究，应拆成分阶段消融，不能作为一次冠军微调。

## 3. 接口兼容矩阵

组合前逐项回答；任何一项未知都先做 contract-smoke，不进入性能排名。

| 接口 | 必须说明 | Fail-closed 条件 |
|---|---|---|
| tensor | 每个输入/输出的 shape、dtype、单位、分辨率和通道语义 | 靠隐式 reshape、广播或补零才能运行 |
| mask | valid/padding/missing-modality/unknown-label 各自语义及传播位置 | 把 padding 当有效观测，或 loss 与 metric 的 mask 不同 |
| coordinate | MD、TVD、TWT、inline/xline、物理 XYZ、采样索引的转换与适用边界 | 将物理深度直接复制为时间，或坐标映射未验证 |
| locality | token 表示整道、局部窗口、体素、patch、井段还是全局样本 | 查询点任务只使用整道 CLS，导致不同深度共享同一表示 |
| alignment | 模态间一对一、软对齐、插值、splat 或注意力的依据 | 使用标签/测试信息完成对齐，或错位对照不退化 |
| missing modality | 缺井、缺地震、缺曲线时的显式行为 | 缺失值被普通零值冒充，或推理强依赖训练期可选模态 |
| information boundary | 特征在预测时是否真实可得，预处理在哪个 fold 拟合 | target 派生量、未来量或 frozen-test 统计进入输入 |
| output semantics | logits/概率/连续值、激活、单位、目标 mask 与后处理 | 训练、验证和发布使用不同定义但未登记 |

### Query-local 硬门

对深度或时间查询任务，地震/基础模型表示必须显式依赖查询坐标。允许局部波形窗口、位置编码、插值 token 或可审计软对齐；只保留整道/整井 CLS 再用于逐深度预测，默认判为语义接口错误。

### 多尺度硬门

高分辨率与低分辨率特征融合时，记录坐标原点、stride、padding 和插值模式。用合成脉冲或已知坐标点验证融合后位置误差；只检查 shape 相同不算对齐通过。

## 4. 融合候选的最小对照组

任何融合路线至少同时执行：

1. 强单模态/单骨干 incumbent；
2. 每个父分支独立模型；
3. 同参数级别的简单 concat 或 late-fusion；
4. proposed fusion；
5. 一个机制反证：错位、shuffle、random-init、移除地质先验或缺模态测试。

若 proposed fusion 没有超过所有可比父模型，不能声称“多模态有效”。若错位或 shuffle 不降低结果，优先怀疑融合分支未被使用或存在泄漏。

## 5. 候选卡合同

每个候选在运行前登记以下字段：

- `candidate_id`：稳定且唯一；
- `failure_evidence`：原始指标/样本组/诊断路径；
- `hypothesis`：一个可证伪句子；
- `primitive_changes`：1–2 个原语及前后差异；
- `interface_contract`：tensor、mask、coordinate、locality、missing modality；
- `paired_ablations`：A-only/B-only/A+B 或单改动去除实验；
- `expected_gain`：主指标、作用样本组和最小实际改善；
- `failure_modes`：至少一个机制失败和一个工程失败；
- `budget_charge`：候选执行次数和 BETU；
- `rejection_rules`：运行前冻结。

LLM 可以起草候选卡，但不能修改 split、主指标、预算、promotion gate，也不能根据 frozen test 结果回写设计。

## 6. 预注册拒绝规则

满足任一条件即拒绝或降级，不用平均分掩盖：

- 数据泄漏、测试回流或输入在真实推理时不可得；
- mask、坐标、token 粒度或输出语义错误；
- 超出登记预算，或通过额外重试获得不公平优势；
- NaN、崩溃、梯度/输出退化且未按统一恢复规则处理；
- 多重复结果方向不一致，置信区间不支持实际提升门；
- 主指标改善但预注册安全指标发生不可接受退化；
- 复杂度显著增加但未达到最小实际改善；
- 机制反证不敏感，无法证明新分支真正被使用。

拒绝候选是有效研究结果。只有出现新数据、新接口或不同机制假设时才允许重开；原配置换名字不算新路线。

## 7. 框架的边界

该框架的统一对象是设计和证据协议，不是强迫所有场景共用同一 backbone。不同场景可以由 3D CNN、树模型、时序基础模型或地质统计方法获胜。Framework 的论文贡献应来自：

- 诊断驱动的候选生成；
- 地学语义接口检查；
- 地质原语与机制反证；
- 同预算执行和稳定性验收；
- 可审计的晋级/拒绝轨迹。

若论文只展示最终分数而没有候选轨迹、消融、稳定性与拒绝证据，它仍然只是手工调参，而不是可验证的模型设计 Framework。
