# 数据卫生 (Data Hygiene) — 治理层第 11 条

> 新数据进 pipeline 前必须体检; 效果变差先查解析不查模型; 异常值先追根因再处理; 外部数据检坐标/单位/时区.

## 4 个子规范

### 1. 新数据接入三步法

新数据源接入前: **看 raw → 交叉验证 → 通过才接 pipeline**. 跳过任一步 = 垃圾进垃圾出但不自知.

- 看 raw: schema, min/max, 单位, 前几行, 分布直方图
- 交叉验证: 跟已有数据做相关 / 物理一致性检查 (如 ERA5 GHI vs 站内 GHI 应 corr > 0.7)
- 通过后才写 merge/join 代码

### 2. 效果变差先检查解析，但根因待证

增加数据/特征后变差，先检查单位、时区、列映射、累积/瞬时和配对；同时核对样本集合是否改变。解析通过后继续检验分布差异、缺测和模型适配，不能预先把原因定为代码bug。划分与业务不匹配走[任务与划分对齐](split-design-contract.md)。

### 3. 异常值先追根因

发现异常值**不机械 clip/删除**. 先判断根因:

| 异常值 | 可能根因 | 正确处理 |
|---|---|---|
| -99 / -999 | 缺失标记 | `na_values`识别；按推理可用性处理缺测 |
| ±32767 / ±3276.7 | int16 传感器极值 | → NaN，保留缺测标志 |
| 65535 / 6553.5 | uint16 溢出 | → NaN，保留缺测标志 |
| 物理超范围 | 传感器故障 / 单位错 | 先查单位, 排除后 → NaN |
| 小负值 (PV power) | 夜间逆变器待机 | 正常, 不 clip |

不能机械clip掩盖异常；原始传感器故障、数据导出与解析错误都可能发生，须用来源证据判定。填补方式服从推理可用性，预测任务不得用未来值做双向插值。

### 4. 外部数据三大坑

接入外部数据 (ERA5 / NWP / 卫星) 必检三项:

- **坐标**: 经纬度对不对站? (匹配后做 corr 检查, 不盲信反推)
- **单位**: K vs °C, J/m² vs W/m², Pa vs hPa, 累积 vs 瞬时
- **时区**: UTC vs local (中国 CST = UTC+8)

三项任一错 = 整个 pipeline 算力打水漂.

### 5. 标签先过记录内不变量，再谈异常值

条件：标签或关键输入来自测量、转录或人工汇编，尤其是小样本、人工数字化或多来源合并的数据。

做法：
- 列出同一条记录内必须成立的关系，逐行检查：校正值与原始值的大小方向、部分不超过整体、组分加和、单调或物理守恒关系、同一实体多字段的单位一致。
- 找出同一实体（同一样品、同一患者、同一设备时刻）的重复记录；值不一致时，在无法判定哪份正确前，所有副本都不作标签。
- 把每行分到三类之一：违反不变量（已证错误，排除）、来源冲突（不确定，排除或单列）、极端但与独立字段自洽（合法稀有值，保留）。三类在训练、验证、测试中按同一规则执行，规则在划分前写定。
- 检查脚本本身先用已知对、已知错的样本跑一遍。

为什么：一个错误标签落在小验证集或测试集上，就能决定选点和结论；错误样本还会被当成“目标异质”的证据，误导后续诊断。

边界：不按目标值大小、阈值或模型误差判定有效性——那是按结果挑样本。只能推测成因（如疑似小数点丢失）时，排除但不改值。

示例：渗透率记录中“Klinkenberg 校正值高于未校正气测值”违反气体滑脱的物理方向，属于已证错误；而一个极高值若校正比例、孔隙度和岩性描述都自洽，就是合法稀有值。

### 6. 区分“性质信号”与“采集上下文”

条件：输入来自仪器、站点、批次或协议不同的多个实体，且模型要用于新实体。

做法：逐个特征问“它变化是因为目标性质，还是因为在哪里、用什么测的”。按实体比较每个特征的取值范围；实体之间几乎不重叠的特征，往往在充当实体标识。对这类特征，改用相对量（与标称值的差、实体内标准化），或删去后做同口径对照。推理时标记超出训练范围的输入。

为什么：采集上下文特征在随机划分里看起来有用，换实体就把模型推到训练范围之外；线性模型和神经网络会外推放大误差，树模型只是截断，同样不可信。

边界：上下文确实影响目标时（例如不同仪器的系统偏差需要校正），保留但要显式建模，并在新实体上验证。

示例：井径曲线主要反映钻头尺寸，换一口不同钻头的井就整体超出训练范围；医学影像中扫描仪型号、病理切片中染色批次同理。

### 7. 标签与输入的空间/时间支撑尺度

条件：标签和输入在不同分辨率上测得（点样品对体积平均测量、瞬时值对时间窗均值）。

做法：先估计标签在输入分辨率内部的变异（如同一输入窗口内多个标签的离散度），把它当作误差下限报告。若改为把标签聚合到输入尺度，在同一批聚合目标上比较“直接用聚合标签训练”和“用原标签训练、再聚合预测”，区分任务变化与模型变化。

为什么：分辨率以下的变化输入看不到，任何模型都学不出来；聚合后分数变高，往往只是平均掉了不可预测的部分。

边界：聚合改变了可声称的能力，报告时写明尺度。

## Checklist

- [ ] 新数据: 看了 raw 前几行 + min/max?
- [ ] 新数据: 跟已有数据做了交叉验证 (corr > 阈值)?
- [ ] 效果变差: 先看 raw vs 解析后对比, 不调模型?
- [ ] 异常值: 查了根因再处理, 不机械 clip?
- [ ] 外部数据: 坐标/单位/时区 三检?
- [ ] 标签: 记录内不变量和重复实体冲突已逐行检查，三类规则在划分前写定?
- [ ] 特征: 按实体比较过取值范围，采集上下文特征已处理或做了对照?
- [ ] 尺度: 标签与输入的支撑尺度差异和误差下限已估计?

## 反模式

🔴 下了 ERA5 直接 merge → 没看 ssrd 是累积还是瞬时 → GHI 变垃圾
🔴 发现 3276°C → 直接 clip 到 60 → 根因是 int16 传感器标记没识别
🔴 加了 NWP 效果变差 → 继续调模型/加特征 → 实际是 diff bug
