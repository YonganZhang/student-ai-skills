# 评测对齐 (Evaluation Alignment) — 治理层第 12 条

> 评测公式/覆盖率/聚合口径/时间对齐必须跟目标标准完全一致; 第三方 pipeline 先 reproduction.

## 5 个子规范

### 1. 指标对齐目标标准

评测跟目标标准 (比赛 / 论文 / 甲方) 一字不差对齐:

- **公式**: MAE / RMSE / MAPE / 自定义 — 是哪个?
- **覆盖率**: 全样本 vs 白天 vs 晴天 — test 段全覆盖, 不是只预测几步
- **聚合口径**: 月均 vs 全集, per-station 还是 overall, 加权还是等权
- **时间对齐**: 预测窗口起止, 月份归属 (t 还是 t+h 的月份)

"差不多" 的评测 = 不可比的数字 = 浪费.

外部标准没有规定尺度或口径时（只写“R² > X”），按第 3–5 条在实验前定下来，写进协议，并说明这是本项目的选择而不是原文要求。

### 2. 第三方 pipeline 先 reproduction

clone 别人的代码后, **先在原作者数据上跑 reproduction**, 验证能复现原作者报告的数字 (容差几个百分点). 通过后才接入自己数据. 不 reproduce = 不知道 baseline 对不对, 后续所有 delta 无意义.

### 3. 评估尺度由目标的生成方式决定

条件：目标跨多个数量级、呈乘性或重尾分布（浓度、渗透率、计数、收入、反应速率等）。

做法：实验前看目标分布，决定在原尺度还是对数（或其他方差稳定变换）尺度上评估；报告前 k 个最大样本占总平方和的比例，说明原尺度指标是否只由少数点决定。训练损失、权重选择准则和最终指标用同一尺度；另一尺度的指标并列报告，不替代主指标。

为什么：原尺度的平方误差类指标会被最大的几个值主导，剔除或调整划分都无法让它稳定；损失、选点和评估尺度不一致时，选点会停在对主指标无意义的位置。

边界：业务损失确实按原尺度计（如按金额结算）时用原尺度，但要报告少数点的主导程度。尺度在看到结果后不能更换；确需更换时重开协议，并保留旧口径结果。

### 4. 分组报告，并与“组均值”基线比较

条件：样本属于均值差异明显的组（类别、站点、实体、岩性、时段）。

做法：除合并指标外，报告组内指标；加一个只预测各组训练均值的基线。模型若不比组均值基线好，说明它只学到了“属于哪一组”。

为什么：组间差异大时，合并 R² 主要来自区分组别，组内的预测能力可能为零甚至为负。

边界：组别本身在部署时不可知时，组均值基线只作诊断，不作可部署对照。

### 5. 小样本评估要报告不确定性和单样本影响

条件：留出集只有几十个独立单元，或一个留出集要支撑上线/验收结论。

做法：对独立单元做 bootstrap 区间；列出误差贡献最大的几个样本及其占比；数据允许时用分组交叉验证代替单次划分。验证与测试的差距落在区间内时，不当作过拟合或泄漏的证据。

为什么：单个样本可能占掉一半以上误差，此时指标衡量的是那个样本，而不是模型。

边界：误差贡献只用于解释；不得据此删样本、改划分或重新挑选模型。

## Checklist

- [ ] 评测公式跟目标标准对齐?
- [ ] test 段全覆盖 (不是只预测 16/96 步)?
- [ ] 月均聚合方式跟标准一致?
- [ ] 第三方代码跑了 reproduction?
- [ ] 数字好得不可置信 → 查覆盖率/泄漏/对齐?
- [ ] 评估尺度在实验前按目标分布定好，损失/选点/评估同尺度?
- [ ] 报告了组内指标和组均值基线?
- [ ] 小留出集报告了区间和单样本误差占比?

## 反模式

🔴 AutoGluon predict 只预测 16 步 → 97.98% → 实际覆盖 0.08%
🔴 前 16 步碰巧夜间 → RMSE ≈ 0 → "准确率 99%"
🔴 MASE leaderboard 分数跟 1-RMSE/Cap 混着比
