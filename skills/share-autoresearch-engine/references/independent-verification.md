# 独立验证不诱导（防一致性偏差）

## 何时触发
- 累积了 50+ 条 finding 后，怀疑里面有错
- 有"机制结论"（X 导致 Y）但没经独立测试
- 用户质疑"是不是搞错了"
- 论文 reviewer 风险预演

## 核心规则
**让 Verifier agent 不读其他 agent 的结论文档，只看原始数据 + 你给的 claim 列表**。

## Prompt 模板

```
任务背景（中性陈述，不要被影响）：
之前几轮跑出 N 条 finding，用户怀疑里面有错，让你独立验证。

你的工作方式：
- **不要先去读** [Claude / 其他 agent 写的结论文档路径列表]
- 自己去原始数据上跑代码，自己得结论
- 跑完之后，再对比原 claim，标"一致 / 部分一致 / 不一致 / 无法验证"
- 写报告到 /tmp/verify-report.md

# N 条待验证 claim（每条带原始数据路径）

## 1. <claim 主题>
**原 claim**: <断言内容>
**你做**:
- <怎么从数据自己算>
- <用什么方法>
- 标"一致 / 部分一致 / 不一致 / 无法验证"

## 2-N ...

# 输出格式
每条 finding 写：
- **现象**: 你跑出的数字
- **原 claim**: 复述
- **判定**: ✅ / 🟡 / 🔴 / ⚠️
- **建议**: 用户要不要相信

最后写"总体怀疑度"：N 条里抽查的 K 条，估计错误率多少？哪类 claim 比较可疑？

预算 ≤ 45 分钟。直接写代码不要长推论。
```

## 关键词

- "**不要先去读**" — 强约束防诱导
- "**中性陈述，不要被影响**" — 弱化背景偏向
- "**自己得结论**" — 强调独立性
- "**机制类 claim 默认怀疑**" — 提醒重点

## 反模式（不要这样写 prompt）

🔴 "请验证 Claude 发现的 X 是否真实成立" → 已经诱导
🔴 "Claude 之前找到 +0.10 提升，请你确认" → 数字提示
🔴 "我们已经知道 site 3 缺数据，请深挖原因" → 已 lock 结论

## 实战例（多站光伏预测项目 R11）

8 条核心 claim 验证后：
- ✅ 2 条全对（GHI 欠刻度 / Site 3→1 lag 90min）
- 🟡 5 条部分一致（机制对但数字不准）
- 🔴 1 条全错（"Site 3 夜间缺 25%" 实际是文件被截到 2020-07-01）

**总判定**：原始数字可信度高，机制解释可信度低。"phantom 原因 / 仪器换型 / 神级修复" 等表述应从断言降级为假设。

## 实施 checklist

- [ ] 收集所有 claim 列表（编号 V1, V2, ...）
- [ ] 写 Verifier prompt（**不带**结论文档路径作为输入）
- [ ] Verifier 跑完后，主 agent 整合到 master list "纠错段"
- [ ] 主 agent 读"机制类"结论 → 标记为假设
- [ ] 更新文档：`raw-llm-reports/<date>-verify.md` + master list 表头警告
