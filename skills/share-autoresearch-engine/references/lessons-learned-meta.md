# 元教训 — 校准直觉

## 核心原则
**直觉每次实验后都需要校准**。把"预测 Δ" vs "实际 Δ" 的差距记下来，下次同类预测自动 adjust。

## 1. 单变量 EDA 相关 ≠ 模型涨幅

**症状**: EDA 看到 corr(X, target) = 0.65，预期 +0.03，实际 +0.0005
**根因**: LGB 已能从其他相关特征近似 X，新特征边际信息少
**校准**: 单变量 corr 推断的涨幅通常**大幅高估**（示例：一个光伏预测项目实测高估 5–60 倍）；不要套固定折扣系数，用本项目的"预测 Δ vs 实际 Δ"记录估偏差因子（见下方校准流水）
**应用**: 每加新特征前问"已有特征是不是已能近似它"

## 2. 机制断言 vs 现象数字

**症状**: "Site 2 phantom 是 SCADA 偏置" → Codex 验证发现 phantom 是真的，原因猜错
**根因**: 看到现象立刻解释，不做实验证伪
**校准**: 机制 = 假设；只有 falsification 实验通过才升结论
**应用**: 写 finding 时，现象用 ✅ 标，机制用 💭 标

## 3. "太好"涨幅默认 leakage

**症状**: AR 残差校正 +0.04~0.06 → 实为 leakage（用了 val target）
**根因**: 跨 horizon 一致涨 + 5σ 跳变，是 leakage 信号
**校准**: 涨 > 0.03 + 跨 horizon 一致 → 默认怀疑，跑 sanity check
**应用**: 写完代码立刻跑 shuffled val sanity check

## 4. Domain 模型 vs 通用预训练

**症状**: 论文 SUNSET 专用 CNN RMSE=51 vs ImageNet ResNet50 frozen RMSE=40
**根因**: 通用预训练数据多 100~1000×，low-level 特征通用
**校准**: 默认先试 frozen 通用 backbone，输了再 from-scratch
**应用**: vision/NLP domain task 第一选项 = pretrained-first

## 5. 1 模型包打 vs per-cell 独立

**症状**: 国网 1 模型 0.7959 vs 8 站独立 0.8986 (+0.103)
**根因**: 8 站容量分布 30~130 MW，物理差异大，全局 averaging 损失精度
**校准**: 多 cell（数据集 / horizon / station）默认跑 4-way PK 再选
**应用**: cell 数 ≥ 5 + 物理差异大 → 必跑 ablation

## 6. LLM 报告倾向"包装"

**症状**: Gemini 写"+0.05" 一查是估计值；Codex"机制可疑"被无视
**根因**: LLM 倾向把猜测包装成结论 + Claude 倾向相信报告
**校准**: 数字必须 reproducible，机制必须 verifier 独立验证
**应用**: 标分级可信度 + Verifier 不诱导跑

## 7. 失败实验也是 evidence

**症状**: 跑了 8 个 reject 实验，没记 lesson → 第 9 次重蹈覆辙
**根因**: reject = "不做了"，没有 lesson 沉淀
**校准**: reject 必写 reason + lesson + 衍生
**应用**: INDEX.md 的 L3_validated_reject 不能只写一行

## 8. Session 切换 / 上下文压缩丢核心

**症状**: 跨会话忘了"AR 是 leaky"，差点上 production
**根因**: 关键 finding 只在对话里没落盘
**校准**: 关键决策必入 `top/decisions/` ADR
**应用**: 每次重要 finding 三件落盘 — INDEX 行 + entry 文件 + ADR

## 9. 用户直觉常对（特别是质疑性的）

**症状**: 用户问"1 个模型怎么可能包打" → 实测 +0.103
**根因**: 用户对 domain / 物理直觉强，AI 默认延续 baseline
**校准**: 用户质疑 → 立刻设计实验验证（不辩护当前做法）
**应用**: 任何用户"我觉得 X 不对"都升 L2_queued

## 10. 沙盒一定划分清楚

**症状**: 改主 pipeline 看效果 → 不可逆 / v1 数字丢了
**根因**: 想省 5 分钟建沙盒，结果花 2 小时回滚
**校准**: 任何方法学改动 → 沙盒先行无例外
**应用**: `_sandbox/exp_<round>_<topic>/` + 冻结的 split 目录（只读，版本号写进目录名）

## 11. 简单拼接 ≠ 拼接本身错，是不看维度语义地拼错

**症状**: 把大模型 embedding 和 baseline 特征直接 `cat`/相加，训练能跑通，但事后发现完全没有增量贡献
**根因**: 没有先搞清楚每个张量每一维代表什么、分辨率是否对齐、拼接维度选得对不对，训练"跑得通"不等于"拼得有意义"
**校准**: 特征拼接本身合法，但拼接前必须列清楚每路张量的语义和维度对齐方式；多模态融合还要选和当前样本规模匹配的融合机制（见 `multimodal-fusion-design.md` 与 `multimodal-fusion-diagnostics.md`）
**应用**: 任何跨模型/跨模态特征融合设计前，先过一遍 `multimodal-fusion-diagnostics.md` 的核心规则 1/2

## 12. 聚合指标涨了 ≠ 融合模块真的起作用，必须实测张量/梯度

**症状**: 融合后整体指标明显提升，但说不清是"新模态真的贡献了信号"还是"其他训练策略优化的功劳"；架构诊断全靠读代码+聚合统计数字推断
**根因**: 聚合指标（mean mIoU、attention entropy 均值等）掩盖了架构层面的具体问题——旁路绕过、gate 被正则压死、attention 坍缩成均匀分布，这些都不会在聚合数字上显式报警
**校准**: 任何"融合模块是否起作用"的判断，都要写一次性诊断脚本实测打印：每个融合节点的真实 shape、反向传播后各分支的梯度范数、attention 的真实分布（不只是聚合 entropy）、去掉可疑旁路后的对照结果
**应用**: 融合架构设计完成、聚合指标看到提升后，先按 `multimodal-fusion-diagnostics.md` 规则 3 选做能区分当前假设的实测检查，再下"融合有效"的结论；实测发现过的具体失败模式见 `multimodal-fusion-diagnostics.md` 的失败模式目录

## 13. 换挂接方式结果变好 ≠ 大模型的预训练知识起作用了

**症状**: 同一个预训练模型，从"logit 层残差"换成"feature 层 cross-attention"接入方式后，指标从没用变成明显提升
**根因**: 新挂接方式可能只是放宽了允许的修正幅度（更大残差上界、去掉硬边界等），跟"预训练知识是否真的被更好利用"是两件事；不补随机初始化对照就无法区分
**校准**: 每次换挂接方式，pretrained 和 random-init 两组对照都要跑，不能只跑出正面结果的那一版就采信
**应用**: 任何"这次终于有用了"的结果，先问"补过随机初始化对照了吗"，没补之前不对外宣称提升来自预训练知识本身

## 14. 换了几个模型族都不行，问题多半在模型之上

**症状**: 树模型、神经网络、线性模型轮流换，加调参、加种子，分数一直差或忽高忽低
**根因**: 瓶颈在模型之上的层级——标签本身有错、指标尺度不对、评估任务和部署任务不一致、特征含采集伪影、标签和输入尺度不匹配；在模型层继续搜索只是在噪声上挑选
**校准**: 两个以上差异明显的模型族同时失败时，暂停模型搜索，自上而下逐层排查：测量与标签有效性（`data-hygiene.md` 第 5–7 条）→ 目标尺度与指标（`evaluation-alignment.md` 第 3–5 条）→ 划分是否对应部署单元（`split-design-contract.md`）→ 特征来源 → 最后才是模型
**应用**: 每轮失败后先问"这一层排除了吗"，没排除就不进入下一轮模型实验。示例：一次小样本回归中，十余轮模型实验之后才发现约 10% 的标签自相矛盾、主指标尺度不合适、交错划分只衡量内插

## 15. 扫描取最大值得到的"发现"只是假设

**症状**: 在一个参数上扫描（偏移、滞后、阈值、子组、特征子集），挑出最好的那个值，就当成"发现了 X"
**根因**: 样本少、候选多时，最大值几乎总能显得显著；这是多重比较，不是证据
**校准**: 这类结论在报告前要满足：样本量足够、零分布保留数据的相关结构、有一个独立的第二信号指向同一结论、判据在扫描前写定。缺任何一项，只能写成"待验证的假设"
**应用**: 诊断阶段的扫描结果不写进结论或 finding，先设计确认实验。示例：用 20 个样本在 ±8 m 内扫描深度偏移，得到高相关的"偏移"；改用全部 208 个样本和第二条曲线后，方向被否定

## 16. 同一接口换十个模块，不是十个独立假设

**症状**: 在一个固定外挂接口上依次试 DCN、注意力、高容量分支、不同融合，全部不涨；于是判断“这些模块都没用”。

**根因**: 变化的是模块身份，固定的是放置位置和接口。所有负结果共享同一个结构假设，彼此相关，不能当独立抽样；真正的搜索轴（位置、原生/外挂、层级）从未打开。

**校准**: 任何模块实验前先过[结构判断门禁](architecture-judgment-gate.md)：写失败模式、结构图、候选位置、机制假设、单轴实验和证伪条件。先用同一模块比较能区分假设的候选位置（含原生位置），再比较模块族。同一接口连续负结果，先审查接口，不直接外推模块家族无效。

**应用**: 报告负结果时写清“模块 × 位置 × 接口 × 数据/预算”的边界；没做位置对照，不写“该模块不适合本任务”；没做原生接入，不写“论文方法无效”。

## 校准流水

每次实验完成后填：

```
预测 Δ: +X (confidence Y%)
实际 Δ: +Z
偏差因子: Z / X = K
更新校准:
  - 同类问题 confidence × 0.5 if K < 0.5
  - 同类问题 E[Δ] / 5 if K < 0.2
  - 该方向暂时降低 ROI 优先级
```

## 反模式

- 🔴 直觉打脸不写 lesson → 下次同类还是相信 70%
- 🔴 机制猜测当结论 → 论文 reviewer 击垮
- 🔴 跑成功就 freeze 不跑 ablation → 错过更优方案
