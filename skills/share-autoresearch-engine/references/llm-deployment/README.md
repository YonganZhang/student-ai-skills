# 大模型推理与部署子流程

归属research-dl-pipeline-base，与其LLM微调流程配合；按需读取，不新增常驻技能。用于已有基座/量化包或微调产物的本地推理、API与服务验收，不要求先微调。

## 按需子技能

请求Strata安装、模型选择、预检、启动/API连接、故障处理或升级时，读取[Strata子技能](strata.md)。只在选用该引擎时读取，不加载整套上游仓库；其他引擎继续按自身原生资料接入。

## 接入原14环节

部署承接11导出/重载、12量化决策与开发复测、13独立确认/冻结/最终测试、14服务/监测/回滚，编号不删并。直接部署已有模型，可从模型/许可/格式身份核查进入，无需重跑OCR、清洗或训练。完整训练链仍见[14环节](../llm-finetuning/execution-checklist.md)，量化/冻结次序沿[发布合同](../llm-finetuning/quantization-and-release.md)。

1. 明确用途：单人交互/离线批处理/并发API，语言、上下文、延迟与质量要求；区分推理资源和训练状态，不用低显存推理证明同显存可微调。
2. 核验模型revision/许可、参数统计口径、权重格式/量化、模板/工具调用协议与引擎实际支持；文件叫GGUF或HF页面生成启动示例不是兼容性实测。
3. 原生引擎候选按[找轮子](../../../dev-find-wheels/SKILL.md)比较，已有已选引擎够用直接复用。GPU吞吐服务考察vLLM/SGLang，CPU/单机GGUF考察llama.cpp/Ollama，分层MoE/offload考察[Strata](strata.md)等；逐架构、逐版本核验，不把候选列表当支持矩阵。
4. 只读盘点可用GPU/显存、RAM/带宽/CPU指令集、实际存储介质和余量；区分原始包/转换副本/运行缓存/KV/并发峰值，模型卡的1M上下文不等于本机验证过1M。缓存与页交换会改变速度，估计不得当实测。
5. 固定版本、隔离安装、先原生plan/预检，确认下载/打包/内存和卡数预算后才获取资产或运行；优先官方SDK/CLI，不另造推理引擎或服务。默认localhost，外网/局域网与密钥/日志按项目授权和ops合同处理。
6. 先短原生smoke与独立重载，再开发集质量、中文/数字/单位/JSON、TTFT、prefill/decode、完成时间、显存/RAM/IO、目标上下文/并发和错误恢复；冻结后才最终test。关闭或明确记录专家剪枝/近似路由/投机解码等，不能把不同质量设置当同一模型同预算比较。
7. 保存实际模型/引擎/配置/硬件/资产SHA、测量口径和失败，按目标服务检查健康/API/超时/回滚；只停止本次拥有的进程。STATIC/DOCUMENTED、SMOKE与目标质量/服务通过分开标记。

第三方skill只能作审阅材料，先查版本、许可、机器路径和副作用；不直接安装其整套宿主配置或复制别人端口/凭证。具体设备、资源、模型选择和测试结果留项目；部署运维操作按所在环境的运维规范（运维技能 `share-docs`（可选，本包未包含））。
