# LLM/VLM 微调与发布子流程

触发：大模型领域适配、指令微调、LoRA/QLoRA、继续预训练、偏好/奖励优化、量化或微调产物部署。由DL Pipeline Base路由到此；通用S0、S1–S9、五个接口合同及fit/select/evaluate/test定义仍以父技能为准。不强套Lightning，不维护另一套训练循环。

## 先按14环节检查完整流程

完整操作真源为[14环节执行清单](execution-checklist.md)：**01任务与验收→02接收/许可→03提取/OCR→04清洗/质量→05去重/污染/划分→06任务数据/标注→07模板/token/监督→08原模型基线/训练配方→09工程与硬件小试→10训练/开发评估→11导出/合并/重载→12部署量化决策/开发复测→13独立确认/冻结/最终测试→14部署/监测。**

新检查挂在对应编号的子步骤下；调整主环节须附旧编号映射。下面的“进入与选择”是入场决策，“S阶段映射”是父流程索引，QLoRA/PTQ/QAT是方法分类；三者均不替代这14环节。对外汇报沿用01–14，逐项区分方法已定义、工程已验和目标任务未验；项目可复制[逐环节状态模板](../../assets/llm-native/stage-status.template.md)。只解释单环节时注明范围，不把局部方法分类当总流程。

## 进入与选择

1. 读项目合同、当前计划与已有证据。按S1明确任务、语言、部署单元、原生指标、许可、预算，再按S0写/复用栈卡。读取[数据与测试](data-and-tests.md)，明确来源簇和测试封存。
2. 先选学习目标，再选更新参数：CPT用正文续写；SFT用正确示范；DPO用偏好对；GRPO等需可信奖励。LoRA/QLoRA/全参不等于学习目标。指令微调属于SFT，不要求再串一次。
3. 按任务、模型与硬件选原生栈：已有可用ms-swift/Factory优先复用，直接HF路线用Transformers/TRL＋PEFT；特大MoE再核验Megatron。不是每个项目重装所有框架。具体固定模板与适配边界见[原生执行](native-pipeline.md)。
4. 每次必须产出[量化决策](quantization-and-release.md)：分别评估训练量化与部署量化；选择采用或暂不采用均写资源、质量、内核依据，未知记待测。不得默认跳过，也不强制一律量化。

## 14环节在父阶段中的映射（不是另一套执行清单）

| 父阶段 | LLM具体产物与验收 |
|---|---|
| S1 / S0 | 任务/语言/指标/部署目标→栈卡、模型与许可、预算；先基线错误再确定改动 |
| S2 | 只读接收→提取/OCR→保守清洗/质量/敏感性→任务样本与标注→模板/token/labels版本 |
| S3 | 去重与来源簇→fit/select/evaluate/test；派生QA/翻译继承簇；校准与量化选择不使用evaluate/test |
| S4 | 原模型＋提示/检索/约束解码对照；评分器正负例、已知可用参照，不凭loss代替任务收益 |
| S5 | 静态/CPU→少量可学习任务→最小可行硬件；核对mask、梯度更新、BF16/分片、optimizer/RNG恢复、严格重载 |
| S6（仅结构改动） | 换结构/adapter机制先过父结构门禁与位置/关闭对照；只换数据/超参不虚构结构创新 |
| S7 | 目标模型pilot→有界训练/搜索→select选checkpoint/解码；失败计成本；截止仍下降按父规则标右删失 |
| S8 | 11导出/按需合并→12部署量化决策与select开发复测→13独立evaluate确认、冻结、最终test→14服务验收；主张轨同预算、多seed/区间 |
| S9 | 全程manifest、资产/模板版本、实际token与GPU/API成本、失败/恢复/导出/服务回执；最终结论不覆盖 |

数据处理、baseline和环境准备可在依赖满足时并行；token化前必须绑定候选tokenizer，所有选择冻结后才进入最终test。工程smoke无需伪造四段科学数据；它只检查接口，不产生领域或稳定收益结论。

## 测试与交付

数据/评分器、模板/监督、实际更新、目标硬件/多卡/恢复、开发效果与遗忘、导出重载、量化质量/性能、独立最终测试、服务/回滚分别留证。必须说明每项对象、版本、样本和覆盖范围；静态PASS不替代模型运行，tiny不替代目标模型。真实部署仍需实际硬件的并发/延迟/显存与业务验收。

默认复用[固定原生模板](../../assets/llm-native/README.md)；模型、数据、资源进配置。新架构/后端/算法/精度超出已验范围时，查对应版本文档并完成局部验收后再扩大，不承诺任意模型仅换名字都可跑。科研创新通过原生dataset/loss/PEFT/reward扩展接口，编排与优化器继续用上游。

项目规模、具体模型、硬件、数据路径、得分和审查结果留在项目；全局只保存通用流程与模板。[来源清单](sources.json)记录版本与适用范围，变更关键设置时核对实际安装版本。项目旧SOP应退役为指针，避免两套活动规范。

## 原生执行覆盖边界

当前固定执行模板覆盖纯文本SFT的BF16 LoRA/QLoRA、ZeRO3与严格恢复配置、合并及无校准BNB部署权重量化。CPT/DPO/GRPO/QAT/全参/VLM在本子流程中是方法与专用上游路由，不是默认资产已可执行；选用时先补对应原生配方和目标验收，未补不启动。
