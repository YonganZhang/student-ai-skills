# LLM端到端执行清单：14环节

这是LLM子流程的完整操作层。父S0/S1–S9是通用研究阶段；01–14是其LLM操作展开，两者保持映射，不互相替代。QLoRA/PTQ/QAT是方法，不是三个端到端阶段。编号为本流程的稳定引用，不宣称全行业只有或必须14步；新增检查先挂子步骤，改变主环节时提供旧编号对应关系。

每项记录输入版本、操作、产物、通过依据及未完成项。项目保留实际状态、路径、预算和证据，本页不代表任何模型已经执行。

| 编号与环节 | 输入→操作→产物 | 完成依据 | 父阶段 |
|---|---|---|---|
| 01 任务与验收定义 | 使用场景→语言/任务/输出形式、指标、保护线、部署约束→任务合同与评分规范 | 正确/错误样例、评价单位、预算、基线和验收口径可核查 | S1/S0 |
| 02 数据接收与许可 | 原始材料→只读接收、来源/用途/许可/敏感性登记→资产清单及SHA | 来源和用途可追溯；未知项隔离待核 | S2 |
| 03 文档提取与OCR | 文档→原生文本提取或扫描OCR→带页码/段落/表格依据的派生文本 | 阅读顺序、数字/单位、漏页/公式抽查；缺失信息显式标记 | S2 |
| 04 保守清洗与质量筛选 | 派生文本→规范化、语言/主题/敏感性/OCR异常检查→保留/降权/待核/排除与日志 | 原件未改、符号单位不过度删除；规则和人工抽查分别留证 | S2 |
| 05 去重、污染与划分 | 文本及来源→精确/近似去重、来源簇、污染核查→冻结fit/select/evaluate/test身份 | 同源变体不跨集合；记录污染检查覆盖范围和缺口 | S3 |
| 06 任务化数据与标注 | 合规fit资料→经核查示范、证据、单位、缺失/冲突处理→SFT或选定目标的数据 | 真实正确性/标注一致性通过；派生QA/翻译继承05来源簇并再查重复 | S2/S3 |
| 07 模板、token与监督 | 任务样本＋候选tokenizer→chat template、EOS、mask、截断/packing检查→版本化token/labels配方 | 有效监督非空、目标位置正确、答案边界完整；各候选分别验 | S2/S5 |
| 08 原模型基线与训练配方 | 任务合同＋开发样本→原模型/提示/检索/约束解码对照，选学习目标/更新参数/精度/预算→基线报告与原生配置 | 基线错误可解释；模型revision、更新参数、超参、训练量化决策与停止条件明确 | S4/S0/S7 |
| 09 工程体检与目标硬件小试 | 配方→静态/CPU、少步、最小可行硬件、多卡/恢复按需测试→工程回执 | 监督/梯度/参数更新、严格重载、实际BF16/显存/吞吐和恢复达到预声明要求 | S5 |
| 10 有界训练与开发评估 | 验收后的配方＋fit→训练/监控，select选点→checkpoint及开发报告 | 任务收益/遗忘/成本分别报；达到停止条件，或明确预算截断而非声称收敛 | S7 |
| 11 导出、合并与重载 | 选中checkpoint→保存adapter或全参、按需合并、独立加载→可追溯部署候选 | base/adapter/tokenizer/template身份完整、数值或输出在预设容差内 | S8 |
| 12 部署量化决策与开发复测 | 11产物＋目标引擎→采用/不采用量化；按方法校准/转换/导出→原精度及候选量化产物对照 | 质量、单位/格式、长上下文、显存、延迟/吞吐达到预设门槛；超限回退 | S8 |
| 13 独立确认、冻结与最终测试 | 开发选定的最终候选→独立evaluate确认→冻结全部选择→一次协议内最终test→最终报告 | evaluate/test未参与学习/校准/选参；最终测试后不回流调本轮模型 | S8 |
| 14 部署与运行监测 | 冻结产物＋最终报告→目标服务验收、版本发布与监测→模型卡/运行回执/回滚方案 | API、并发、上下文、故障、质量、资源与回滚可验证；部署调优遵守冻结边界 | S8/S9 |

## 保留主编号，展开重要子步骤

- **01.1–01.3**：定任务与语言；评分器用金标、空预测、错数字/单位等正负例自检；明确资源/许可/保护线。评分器必须在模型比较前合格。
- **05.1–05.4**：精确重复；近似/同源簇；污染覆盖核查；按独立单位冻结四段。已有冻结边界先继承，06后的派生变体再查一次，不重新随机全库。
- **07.1–07.4**：候选模型tokenizer与角色/EOS；labels/loss mask；长度与有效token统计；截断/packing边界实测。候选tokenizer在07前绑定，08比较后定最终基座；换基座须回到07复验。
- **08.1–08.5**：基座/提示/检索/约束基线；SFT/CPT/偏好/奖励学习目标；LoRA/QLoRA/全参更新范围；BF16等计算精度与训练量化决策；lr/rank/batch/长度/预算/停止条件。模型规模与任务目标、更新范围分别选择。DPO先审chosen/rejected及其来源簇、偏好一致性，并核验冻结参考策略或所选reference-free变体；GRPO等先验奖励/验证器正负例、防奖励投机、采样与token预算、参考/KL配置和停止条件，缺原生配方不执行。
- **09.1–09.5**：静态/CPU格式预检；tiny少步及实际更新（训练输入仅fit或合成夹具，select只作开发验证，evaluate/test均不参与工程smoke）；目标模型最小可行硬件小试；按需多卡通信/分片和性能；凡声明支持恢复或计划中断续训，保存/恢复optimizer、scheduler、RNG、数据顺序并做连续/恢复对照。放不下单卡可直接分片，测试顺序不要求先OOM。
- **10.1–10.4**：有界正式作业；曲线/梯度/有效token/显存/速度；select选择checkpoint/解码及通用能力回归；失败/中断/预算用尽如实报告。结构创新先过父S6，非所有训练必做。
- **11.1–11.3**：保存身份完整的adapter/全参；按部署需要用匹配基座原生合并；独立进程重载并检验等价。支持base＋adapter时不强制合并。
- **12.1–12.6**：部署量化决策；方法/位数/硬件内核核验；需要时用fit/select/专用calibration校准；量化导出及重载；开发质量与性能对照；选定候选或退回原精度。BNB等无校准路线不伪造校准，AWQ/GPTQ等按原生要求执行。evaluate/test均不得校准。
- **13.1–13.3**：独立evaluate确认；冻结checkpoint、数据配方、量化、模板、解码、推理精度和选择规则；按预声明协议开启最终test。独立确认不用于反复挑候选；若据此改方案，则记录确认集已受影响并按父合同重新建立独立确认，不能仍报原集合独立。
- **14.1–14.3**：目标服务功能/性能验收；许可/版本/模型卡/回滚；监测漂移与新版本触发。测试后任何影响输出语义的量化、模板、解码或内核变化属于新候选，回到相应开发环节重验；服务测试不能成为绕过最终测试的调参入口。

## 量化与其他学习方法接入哪里

| 方法/检查 | 接入环节 | 含义与依赖 |
|---|---|---|
| 训练量化/QLoRA | 08决策→09支持与更新检查→10训练 | 冻结低位数基座、训练adapter；计算dtype可能BF16，不代表部署量化已验 |
| 部署量化/PTQ | 12决策/按需校准与导出/开发复测→13最终验收→14服务 | 可选择保持原精度；不论采用与否均记录理由 |
| QAT | 08确定目标及预算→09原生小试→10训练分支→11–14导出验收 | 量化影响纳入训练；须有原生配方、对照与资源，不是PTQ前的固定必做步骤 |
| CPT/SFT/DPO/GRPO等 | 06数据格式→08选择目标→09–10对应原生配方与评估 | CPT可在SFT前追加；DPO/RL按错误与目标另开支路，不规定所有模型必须全部串行 |
| 数据/评分器/模板/恢复/质量/导出/量化/最终/服务测试 | 01–14对应验收点 | 测试贯穿全流程；一项smoke通过不能替代全部验收 |
| 版本、成本、失败与证据 | 01–14全程，归父S9 | 准备、训练、评审、校准、导出和服务成本均记账，不只记optimizer时长 |

执行分工见[原生Pipeline](native-pipeline.md)、[数据与测试](data-and-tests.md)、[量化发布细则](quantization-and-release.md)。官方依据见[来源清单](sources.json)；这些环节是对资料和实现的操作归纳，不把本地编号冒称某一家官方统一标准。
