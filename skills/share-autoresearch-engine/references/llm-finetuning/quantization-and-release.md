# 量化决策、导出与部署

量化评估是必需项，量化执行按证据选择。先填模板中的训练与部署两份决策；采用/不采用/待测都有理由、版本与资源记录。

## 先分位置，再选格式

| 路线 | 位置与约束 |
|---|---|
| BF16/FP16＋LoRA | 高精度冻结基座与adapter；资源足够且部署无压缩要求时可以保持原精度，不把不量化当遗漏 |
| QLoRA | 训练时冻结低位数基座、训练adapter；存储位数、计算dtype、优化器状态分别核验；不是对所有4bit权重全参训练，也不是已完成部署量化 |
| PTQ | 训练产物选定后，按目标引擎/设备量化；方法要求时校准，再做开发质量与性能比较 |
| QAT | 专门训练分支，PTQ不能满足目标且原生实现支持时另给预算/对照；不要求每个任务都做 |

预算包含总驻留权重（MoE不是只存激活参数）、未量化张量/量化尺度、adapter与optimizer、激活/重计算、临时buffer、KV cache/并发、加载/合并/导出/校准峰值与磁盘副本。不能用发布文件大小或参数×位数替代峰值实测。CPU offload要计带宽和时间，少卡可加载不等于租期内可训。

核对模型层/专家结构、量化库、原生训练器、GPU计算能力/内核和推理器支持；FP8/FP4文件可读不代表该卡有原生加速。小位数不保证更快，训练支持不等于可序列化/部署。使用框架已有支持，不能把未经核验的通用4bit推荐给所有MoE。

## 固定发布顺序

1. 从select选择训练checkpoint，记录原精度基准；保存匹配的base revision、adapter、tokenizer/template和实际配置。
2. 使用独立进程严格加载；引擎支持base＋adapter时可不合并。需要独立权重时按原生工具，用适合该合并路线的匹配基座合并；全参没有adapter合并。训练的量化基座不可随意当高精度基座。
3. 依部署约束选择不量化或候选PTQ；校准仅使用许可明确、具有代表性的fit/select，或单独冻结的calibration集合；不得使用evaluate/test。记录样本ID与来源簇，凡用于校准/量化选择的数据不能再称独立evaluate。
4. 比较原精度/合并/量化产物的任务质量、数值/单位/结构化输出、显存、延迟/吞吐与长上下文；提前约定容忍度，超限换配方或回退。未测试无固定默认容忍百分比。
5. 独立evaluate确认后冻结checkpoint、量化/模板/解码/部署目标，再按父合同开启最终test。若原精度与量化都作为正式产物，预声明并一起报告，不能看test后改量化。
6. 按实际引擎构建/加载服务，做API、并发、上下文、超时/资源与回滚验收；记录模型卡/许可/版本/失败边界与成本。TensorRT的构建引擎步骤不强加其他推理器。

校准与发布量化并非所有格式都需要，硬件/引擎转换也不一定无损。保留原精度参考与可恢复checkpoint，另存每种派生产物；8bit量化推理、8bit优化器、KV cache量化也是不同设置。

已有基座/量化包的独立部署与目标服务验收见[大模型部署子流程](../llm-deployment/README.md)；微调14环节不变，部署可独立进入，不要求重训。
