# 多模态/跨模型融合：诊断菜单与已知失败模式

> 定位：本页保留 2026-07-30 版融合设计笔记中的张量语义检查、规模匹配、实测诊断与失败模式目录，作为**按需诊断菜单**。入口与最小实验合同以 [multimodal-fusion-design.md](multimodal-fusion-design.md) 和 [端到端 SOP](end-to-end-learning-sop.md) 为准；两者冲突时以入口页为准（例如入口页规定机制反证“按假设择一，不强制每次开全矩阵”，本页的“五类实测”据此理解为可选诊断项，不是每次实验的硬门）。

## 何时触发

- 要把一个预训练大模型（视觉/时序/体数据基础模型等）的特征接入一个已有的强 baseline
- 任何"把 A 模型的输出和 B 模型的输出拼在一起"的融合设计
- 聚合指标显示"融合后有提升"但说不清提升从哪来
- 怀疑一个融合模块"接了但没真的起作用"

## 核心规则 1：拼接前必须先搞懂每个张量是什么

"特征拼接"本身不是问题，**不看维度语义、不看每个张量代表什么就直接拼**才是问题。拼接前必须回答：

- 这个张量的每一维分别代表什么（batch / channel / 空间位置 / 时间步 / patch 索引）？
- 两路特征拼接时，空间/时间分辨率是否对齐？如果不对齐，是靠插值/池化/广播强行对齐的，还是本来就同尺度？
- 拼接维度选对了吗（沿 channel 拼 vs 沿 sequence 拼，语义完全不同）？
- 两路特征的数值量级/分布是否可比（一路是 logit，一路是归一化 embedding，直接相加/拼接前有没有做过对齐）？

**不回答清楚这几条就直接 `torch.cat` 或 `+`，等于把两个不知道语义关系的向量强行怼在一起，即便训练能跑通、loss 能下降，也无法判断学到的是不是有意义的东西。**

## 核心规则 2：多模态融合需要与数据规模匹配的融合机制，而不是任选一个

- 数据量极小（几十到几百样本）时，全量 cross-attention/transformer 融合模块本身的参数量可能远超训练样本数，几乎必然"先过拟合、后期梯度噪声主导"——融合机制的复杂度要和可用样本量匹配，不是"越复杂越先进就越好"。
- 常见可选融合机制，按数据规模从小到大：
  1. **降维后直接拼接进现有强 baseline 的输入特征**（stacking）——不单独训练新的融合网络，让原 baseline 自己的正则化/特征选择机制决定新特征有没有用。适合样本量个位数到几百。
  2. **门控残差**（gate 控制的加权修正）——新模态的贡献可以收缩到 0，退化为纯 baseline，下限有保证。适合样本量几百到几千，且必须配合"gate=0 精确退化"这类运行时断言验证。
  3. **cross-attention 融合**——参数量最大、表达力最强，但也最容易在小样本下学不动或被正则压成 no-op。适合样本量至少几千起，且要专门验证 attention 是否真的学到了非均匀模式（见规则 3）。
- 换融合机制不是"越花哨越好"，是要匹配当前样本规模；样本规模不够时，优先选简单机制，而不是一上来就上最复杂的方案再事后调参救场。

## 核心规则 3：聚合指标不能证明架构在起作用，必须实测张量/梯度

**这是最容易被忽视、也是本轮实践里反复验证有效的一条**：仅凭"融合后整体指标提升/下降了多少"这类聚合数字，无法判断融合模块本身是否真的按设计工作。必须直接跑一次前向+反向，打印以下几类实测证据：

1. **每个融合节点的真实 tensor shape**：query/key/value 构造后的 shape、attention 输出的 shape、拼接前后的 shape——确认没有静默的维度错配、没有被意外 broadcast、没有被 reshape 成信息坍缩的形状。
2. **反向传播后各分支的梯度范数**：新模态分支（如 cross-attention 的 key/value 投影）和旧 baseline 分支（如 query 直连/残差旁路）各自的 `.grad.norm()`，对比相对大小。如果新模态分支梯度范数远小于旧分支，说明这条分支根本没有获得有效的学习信号，不管架构设计得多精巧。
3. **attention weight 的实际分布，而不只是聚合 entropy**：抽几个真实样本打印完整的 attention weight 矩阵。如果权重接近均匀分布，说明这个"注意力机制"实际上退化成了"对新模态特征做全局平均后当一个常数上下文注入"，没有学到真正的选择性路由——这种情况下即便整体指标涨了，涨的也大概率不是来自"注意力真的选对了该关注的位置"。
4. **去掉可疑旁路的对照实验**：如果架构里存在"新模态信息可以被绕过"的捷径（比如旧模态的特征在网络里同时走了两条路径——一条经过融合模块，一条直接跳过融合模块拼接到输出层），要单独跑一次"去掉旁路、强制信息必须经过融合模块"的对照，看指标和 attention 分布是否发生变化。如果去掉旁路后指标不变、attention 依然均匀，说明新模态确实没有可用信号；如果指标明显变化，说明之前的"融合有效"只是旁路在起作用，融合模块本身是摆设。
5. **checkpoint 选择方式**：确认训练循环是否有 early stopping / best-checkpoint 保存，还是无条件用最后一步的模型做评测——固定步数训练容易出现"loss 先降后升"，此时用最后一步权重报告出来的数字很可能不是模型学出的最佳状态，而是过拟合后被噪声带偏的末态。

**只凭聚合数字得出的"融合模块起作用了/没起作用"只是假说；要下结论时，按当前假设从上面五类里选能区分它的实测项。**

## 已知的具体失败模式目录（实测发现过的，遇到类似现象时优先怀疑这些）

| 现象 | 可能的根因 | 怎么验证 |
|---|---|---|
| 门控/gate 值几乎不偏离初始化值 | 正则化项（鼓励 gate 收缩）的梯度压过了任务 loss 传给 gate 的梯度；也可能是训练步数太少、gate 根本没收到足够信号 | 打印每步 task_loss 和正则化 loss 各自对 gate 参数的梯度贡献，对比量级 |
| attention 权重接近均匀分布 | 旁路绕过（见规则3第4条）；或 weight_decay 把 query-key 投影压得太小，点积趋近 0，softmax 后必然均匀 | 去掉旁路对照实验；关掉/调小 weight_decay 重跑 |
| 融合后指标 ≈ 只做"其他工程优化"（更好的正则化/校准/训练策略）时的指标 | 提升主要来自训练策略本身，新模态没有增量贡献 | 单独跑一版"只做其他优化、不接新模态"的对照，与"接了新模态"版本相减 |
| 同一个预训练模型，换一种挂接方式（比如从 logit 层残差换成 feature 层 cross-attention）结果从"没用"变"有用" | 新方案可能只是放宽了允许的修正幅度（更大的残差上界、去掉硬边界等），不代表预训练知识本身被更好地利用了 | 必须补随机初始化权重对照，两种挂接方式都要跑，不能只跑得出正面结果的那一版就下结论 |
| 参数量远大于训练样本数的融合子网络，训练 loss 先降后升 | 从零初始化的融合模块在极小样本下几乎必然"先过拟合、后期梯度噪声主导" | 加 early stopping；或换成规则2里更简单的融合机制 |

## Checklist

- [ ] 拼接前列清楚每个张量每一维的语义，确认拼接维度和分辨率对齐方式
- [ ] 融合机制复杂度与当前样本规模匹配（个位数~百级样本不上全量 cross-attention）
- [ ] 写了独立的诊断脚本，实测打印了每个融合节点的真实 shape
- [ ] 实测打印了反向传播后新模态分支 vs 旧分支的梯度范数对比
- [ ] 检查过 attention/gate 的实际分布，不是只看聚合 entropy/mean
- [ ] 如果架构里存在潜在旁路，跑过"去掉旁路"的对照实验
- [ ] 确认训练用了 early stopping / best-checkpoint，而不是无条件用最后一步
- [ ] 单独跑过"只做其他优化、不接新模态"的对照，把"新模态的增量贡献"和"其他优化的贡献"分开报告
- [ ] 同一模型换挂接方式前后都跑过随机初始化对照，不只跑正面结果的那一版

## 反模式

- 🔴 不看维度语义直接 `torch.cat`，训练能跑通就当作"拼接没问题"
- 🔴 只看整体指标涨了就归因于"新模态大模型起作用了"，不拆解训练策略本身的贡献
- 🔴 只看 attention_entropy 之类的聚合统计量判断"学到了有意义的模式"，不打印真实 attention 矩阵
- 🔴 换了挂接方式后结果变好就直接采信，不重新做随机初始化对照
- 🔴 固定步数训练、无 early stopping，直接用最后一步模型的指标下结论
