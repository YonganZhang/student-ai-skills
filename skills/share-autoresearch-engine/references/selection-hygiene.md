# 选择卫生 (Selection Hygiene) — 每一个"挑一个"都要花掉一份 held-out

## 条件

训练之外还存在任何需要"挑一个"的自由度时生效：

- 取哪一步的权重（早停点 / best checkpoint）
- 判定阈值、NMS 距离、最小连通面积等后处理超参
- 解码器 / 峰值检测器 / 分割后处理的族与参数
- 集成权重、校准温度、特征选择、超参搜索的胜者

这些都是**模型选择**，不是训练。它们各自消耗一份泛化预算。

## 不变量

### 1. 选择必须在模型没有拟合过的数据上做

`fit` 用过的行不能再用来挑权重或挑阈值。训练集上的分数是模型对它自己记忆的评分，
不是能力的度量。样本少不是豁免理由 —— 样本少恰恰是最容易被记住、最需要 held-out 的场景。

评测集同样不行：那是最终裁决面。三段式是最低要求：**fit / select / evaluate**。

### 2. 选择目标必须先证明有区分力，再取 argmax

取 argmax 之前先看候选分数的分布。**当 best 与 2nd 的差距落在选择集的噪声量级内，
argmax 就不是选择，是抽签** —— 而抽到的那个签会被原封不动地用到评测集上。

必须报告并在饱和时拒绝：

```
best − 2nd
top-k 跨度（k≈10）
并列在 best 上的候选数
```

任何一项显示饱和，就说明这个选择集已经没有信息，应当扩大选择集或缩小候选空间，
而不是接受 argmax 的结果。

### 3. 选择集的划分不能随训练 seed 变

划分要绑定数据种子，不绑训练种子。否则每个 repeat 都在换尺子，seed 间的方差测的是
划分，不是架构。

### 4. 用了验证集以外信息的选择，要标成事后选择

条件：最终交付或上线的模型，不是协议里按验证集选出的主模型——例如看过测试集、外部核验集或用户反馈后改选。

做法：同时保留两条记录：协议主模型及其测试结果（作为正式结论）、实际交付模型及其选择依据。交付模型在这些集合上的分数标为“事后选择，偏乐观”，写进模型元数据；之后再有独立数据时，用它重新核验交付模型。

为什么：用于挑选的集合不能再无偏地评价被挑中的模型。不标注时，下游会把乐观分数当成泛化能力。

边界：产品上按全部证据选交付模型是合理的；问题只在于把事后选择的分数当作独立评估。

### 5. 新模块的选点与读数

条件：比较中有新接入的分支（尤其零初始化、门控、残差插座），且 checkpoint 按 select 指标选出。

做法：每个实验格记录选中步、第一个可选验证点、新分支开始有效（有效贡献 RMS(Δ)/RMS(主路) 明显大于 0）的步数、选中时的有效贡献。选中步等于第一个可选点、早于分支解锁或选中时有效贡献约为 0 → 该格结论记"未测"，不记"无效"。同时报告与阈值无关的指标（AP、AUC、每样本最优）与重选阈值后的工作点指标，两者不一致时单列"阈值迁移"。强制关闭模块后分数整体平移时，先重选阈值或用与阈值无关的指标再比。

为什么：零初始化分支在头几百步几乎不贡献；若 select 指标在第一个验证点就最优，比较的其实是"父模型 + 未训练分支"。硬性规定最晚可选步会制造另一种偏差（被迫选在门槛上），优先用"按主指标选点 + 记录选中步与有效贡献"判断。

工具：`scripts/selection_exposure_check.py`（读验证曲线与有效贡献，返回 tested/untested）；插座与有效贡献钩子见 `mlgain/scripts/module_probe.py`（本包未包含）。

## 边界

- **与 `leakage-checklist.md` 的区别**：那份查的是 *特征* 泄漏，触发信号是"数字太好"。
  本条查的是 *选择* 泄漏，典型症状是**数字很吵** —— seed 间方差异常大、排名不稳、
  换个 seed 冠军就变。"太好则查泄漏"的直觉在这里完全不会报警，这是它需要单独一条的原因。
- **与 `evaluation-alignment.md` 的区别**：那份管指标口径与目标标准对齐；本条管
  决定权重与超参时用了谁的数据。
- 纯超参搜索的搜索策略、预算分配不在此条，归 `architecture-ablation.md`。

## 验证

写完训练/评测代码后，逐条回答：

- [ ] 训练循环里有没有 `best_state` / 早停？没有就是在取最后一步 —— 那一步凭什么是对的？
- [ ] 阈值、后处理超参是在哪一批数据上选的？grep 选择函数的入参，确认不是 `train`。
- [ ] 选择集有多少样本？模型在它上面跑了多少个 epoch？（`steps × batch ÷ 样本数`）
- [ ] 选择目标的 best−2nd 是多少？并列几个？
- [ ] 划分的随机源是数据种子还是训练种子？
- [ ] 同一模型跨 seed 的**分数** sd，与模型之间的 sd 相比是多少？比值 < 2 时排名不成立。

诊断动作：把同一模型多个 seed 选出的超参列出来。**若 N 个 seed 选出接近 N 个不同的
配置，而它们在选择集上的分数几乎相同，选择层就是当前的主噪声源** —— 此时加 seed、
换聚合函数、调训练预算都无效，必须先修选择。

## 案例（证据，非规则）

原子识别 benchmark 家族筛选，9 架构 × 5 库：

- 训练 3000 步、7 张图（≈1714 epoch），随后在**同样这 7 张图**上从 56 个解码器候选里选 argmax
- 结果：56 个候选在训练集上**精确并列于 F1 = 1.0000**，best−2nd = 0.0000
- 6 个 seed 选出 5 个不同解码器；抽到 `min_area=1` 而非 `min_area=8` 的那个 seed，
  评测分数掉 **0.35**
- 同期训练 loss 跨 seed 的 sd 只有 **0.005**（相对 0.4%），最终分数 sd 却是 **0.083**（相对 13%）
  —— 训练极其稳定，乱的全在选择层
- 同一 pipeline 早先还有一次同类：解码器标定的真值全空 → 评分器对"空真值+空预测"返回
  F1 = 1.0 → 零检出解码器被打成满分并冻结

前一轮排查曾把这归因于"训练方差大 / 没收敛"，据此加 seed 与换聚合函数，全部无效。
**训练 loss 稳定而评测分数不稳定，就是选择层出问题的指纹。**
