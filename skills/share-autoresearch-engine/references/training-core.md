# 训练判断核心：把网络训好，而不是只把流程跑通

这是本 skill 的第一层。先判断模型在发生什么，再谈改结构、融合和调参。工程门禁、回执、结构卡是第二层护栏，不能替代这一层。

## 1. 先定义“好”是什么

训练前必须写清四件事，否则后面的 loss 和曲线没有解释力：

1. **任务**：分类、回归、检测、分割、追踪、匹配、排序，还是多任务。
2. **评价器**：最终分数怎么算；阈值、匹配、聚合、忽略区、后处理是什么。
3. **数据单位**：一张图、一个 patch、一个病人、一个 time series、一个 track；split 必须按这个单位切。
4. **baseline**：同数据、同 split、同主预算轴、同评价器的强 baseline 是什么。

**训练 loss 是优化目标，不是最终评价。** loss 降、指标不升，先查评价器、阈值、选择指标和部署输入，不要先庆祝。

## 2. 过拟合与欠拟合：看曲线，不看单个点

不要用“train loss 低”或“val loss 高”单独下结论。先保证两条曲线**可比**：固定 fit 子集，用 `eval()`、关闭随机增强、同一硬标签目标和同一 reduction 计算 train-eval loss；训练目标（带增强/软标签/正则）另存一条。训练目标与验证目标不同、batch 组成不同、reduction 不同，gap 本身不诊断拟合。

至少同时看：

- 可比的 train-eval / val loss 的绝对值和 gap；
- 两条曲线随 step 的形状；
- 随数据量、模型容量、训练步数的变化；
- 多 seed 的波动；
- 错误样本的类型，而不是只看平均值。

| 现象 | 更可能的判断 | 先做什么 |
|---|---|---|
| train 高、val 高、gap 小，且加容量/步数还能降 | 欠拟合或优化不足 | 加容量、训久、调 lr、改损失、查特征/标签 |
| train 低、val 高、gap 随训练扩大 | 过拟合 | 加数据/增强、正则、dropout、weight decay、早停、减小模型、预训练、融合 |
| train 低、val 低，但部署/测试差 | 仅凭拟合无法解释；优先查分布偏移、预处理、评价器、前后处理 | 查数据管线与部署一致性 |
| train 高、val 低 | 不能直接判欠拟合；可能是 val 更容易、泄漏、预处理不一致、正则/增强差异 | 先查 split、增强、归一化、标签、loss 口径 |
| 两者都高、gap 小，怎么调都不降 | 仅凭曲线不能判；可能是优化问题、标签噪声、loss 不匹配、梯度断路 | 先做记忆探针和梯度检查，不直接归因 |
| train 和 val 都低，但指标饱和/并列 | 先查评价分辨率/选择，不要用“拟合好”解释 | 扩大选择集、换更细指标、看并列与置信区间 |

### 诊断顺序

1. **记忆探针：固定样本、固定增强、可达标签，能否把 loss 压到预期下限？**
   不能：先查代码、标签、loss、优化器、梯度、shape、mask、ignore_index。强增强、软标签、冻结大部分参数、随机任务不保证 loss 接近零，要写预期下限或“相对初始下降”标准。
2. **学习信号探针：真实增强/真实目标下，loss 是否相对初始化稳定下降？**
   不降：仍是优化/数据/标签/接线问题；下降但 val 差，才进入泛化讨论。
3. **train/val 曲线和 gap 怎么变？**
   只有两条曲线可比时，gap 才说明问题；gap 小且两者都高更像优化/容量，gap 大更像过拟合/分布差异。平台只说明当前配方平台，不等于收敛。
4. **错误长什么样？**
   某一类、某一尺度、某一视图、某一标签、某些边界；平均值会掩盖这些问题。
5. **换 seed、换 split、换数据量还成立吗？**
   单次曲线不是结论；至少看波动和趋势。

### 常见误判

- **把分布偏移当欠拟合**：val 高但 train 低，不一定是模型容量不够；先查 val 与 train 的分布、预处理、采集条件。
- **把标签噪声当欠拟合**：损失降不下去，可能是错标/多标/空标；看真实样本和错误样本。
- **把 BN 的小 batch 问题当模型不行**：小 N 不必然失效；看统计轴、每卡有效样本、空间相关性和领域偏移。可试 GroupNorm、SyncBN 或冻结统计量，但不要当万能替换。
- **把增强不一致当泛化差**：训练和验证的归一化、裁剪、插值、通道顺序不一致，val 会无故变差。
- **把验证集反复选择当过拟合**：train/val 都低仍可能过拟合验证集；看候选数、选择次数和独立复现。
- **把选择噪声当模型波动**：验证集太小、候选太多、候选间差异接近噪声，排名本身不可信。

## 3. Loss 怎么选

先让 loss 和输出/标签的数学形式匹配，再谈调参。下表是**候选**，不是“任务→唯一 loss”的定律；每个选择都要能说出估计目标（均值/中位数/分位数/似然）和失败代价。

| 任务/输出 | 候选 loss | 选择条件与边界 |
|---|---|---|
| 回归 | MSE / MAE / Huber / quantile | MSE 对应高斯噪声/均值；MAE 对应中位数、对异常值更稳；Huber 是折中；要区间用 quantile。异常值多不是换 MAE 的唯一理由，先看标签质量 |
| 二分类，独立标签 | BCEWithLogits 基线 | 正负极不平衡可加 class weight/focal；软标签有不可消除的下限；不要先 sigmoid |
| 多分类 | cross entropy 基线 | 长尾/噪声可试 class weight、focal、label smoothing；label smoothing 不自动修复错标，也不保证校准 |
| 分割 | CE 基线；Dice/边界项按需 | CE 是合法基线；Dice 要定义背景、空 mask、按图/按 batch 聚合；边界项要定义距离/容差 |
| 检测 | 分类 + 框回归 + 质量/objectness（按 detector） | 现代 anchor-free/DETR 类不一定有独立 objectness；按匹配器和质量分数写，不要套旧 SSD 公式 |
| 追踪/匹配 | 对比/三元组/匹配 loss + 任务 loss | 负样本采样、温度、难负样本决定成败；和跟踪指标（HOTA/IDF1）分开看 |
| 多任务 | 每任务 loss 加权和 | 先单任务 baseline；权重看 loss 尺度、梯度范数/冲突、验证指标；不要只看总 loss |

### Loss 检查清单

- **完美预测下限**：完美输出时 loss 是否达到理论下限？软目标 BCE 的下限不是 0；复合 loss 要逐项推导。
- **logits / 概率**：`BCEWithLogitsLoss` 前不要再 sigmoid；CE 前不要再 softmax；软标签是否满足概率/归一化条件。
- **reduction / 有效分母**：mean/sum 与 batch、多任务权重、mask 后的有效元素数是否一致；不要用“平均的 batch 平均”冒充全局平均。
- **ignore_index / mask**：忽略区是否真的不产生梯度；空 mask、全背景、部分标注是 ignore 还是负例，必须由数据契约定义。
- **类别权重**：权重是否按频率倒数拍脑袋；是否和重采样双重补偿；是否让模型只会预测多数类。
- **优化器语义**：Adam 的 L2 正则和 AdamW 的 decoupled weight decay 不是一回事；bias/norm 是否排除在 weight decay 外，参照配方做对照。
- **数值稳定**：AMP 下 loss 是否溢出；log(0)、除零、NaN 从哪里来；梯度累积时 unscale/clip/step 的顺序。
- **loss 与指标对齐**：优化 proxy loss 是否真的在优化部署指标；不一致时用 select 指标选点，不要只盯 loss。

## 4. 训练策略与超参数

调参顺序比搜索空间更重要。默认顺序：

1. **数据和 baseline 先对**：叠图、标签、增强、评价器、记忆探针。
2. **优化先稳**：lr、warmup、batch size、梯度裁剪、AMP、初始化。
3. **预算够不够**：先选主预算轴，再看趋势/噪声；不要用步数相同但曝光/计算不同的曲线判慢热结构。
4. **正则再上**：weight decay、dropout、label smoothing、早停、数据增强。
5. **结构最后**：一次只改一个变量，和同主预算轴 baseline 比。

### 学习率与 schedule

- 先做 lr range/短扫，不要凭感觉；最优点贴边界就扩范围。
- 大 batch 通常配更高 lr；但先保证优化稳定，再谈线性缩放。
- warmup 对 Transformer、大 batch、新模块、零初始化分支尤其重要。
- cosine/step/plateau 都可以；关键是与总步数匹配，不要中途改 schedule 还比较曲线。
- 观察到损失尖峰/NaN：先降 lr、加 grad clip、查 AMP，不要先改结构。

### Batch size、正则与早停

- batch size 影响 BN、lr、梯度噪声和显存；比较模型时固定，或同时重调依赖项。
- weight decay 不是越大越好；先看 train/val gap，再决定加在哪。
- dropout 在卷积/Transformer/小数据上的行为不同；不要在推理时忘记 eval。
- 早停要有 patience 和最小步数；不要在第一轮验证就停，也不要在噪声上停。
- 小数据优先：预训练、冻结/分层 lr、强增强、交叉验证、简单模型；不要一上来堆大模型。

### 预算：先选主轴，再谈“同预算”

- **主预算轴**：样本曝光（examples/images/tokens）、optimizer updates、FLOPs、墙钟时间，四选一作为主约束，其余记录。改 batch 后“同 step”不等于同曝光；改模型后“同步数”不等于同计算。
- **pilot** 用来发现 pipeline 问题、估显存/速度、看曲线形态；明确标为 exploration。早期排名不保证预测足预算排名，至少保留少量慢热配置跑满。
- **预算阶梯**：短预算看趋势，逐步加到能判断 plateau 的预算；不要一开始拍一个巨大预算，也不要用短预算判死慢热模型。
- **正式比较**：同主预算轴、同 split、同评价器、多 seed；pilot 不能当最终证据。
- 曲线到 cap 仍在降：只说明**右删失**，不证明“预算不足”或“未收敛”；结合趋势/噪声再决定扩预算。不能扩就标右删失，不写“收敛”。
- **改 schedule 要重跑**：cosine 总长度变了，已走过的 lr 路径也变了；严格 resume 和“重设 schedule 重跑”是两种实验，不能混。

## 5. 归一化怎么选

归一化不是“加上 BN 就行”，它改变优化地形、batch 依赖和推理行为。

| 类型 | 适合 | 注意 |
|---|---|---|
| BatchNorm | 统计轴有效、CNN、分类/检测 backbone | BN2d 统计覆盖 N,H,W；小 N 不必然失效；train/eval 行为不同；DDP 不强制 SyncBN |
| LayerNorm | Transformer、RNN、小 batch、序列 | 在特征维归一化；对通道/空间布局敏感；和 BN 的统计轴不同 |
| GroupNorm | 小 batch、分割、检测、视频 | 组数影响容量；是候选，不是 BN 的自动替代 |
| InstanceNorm | 风格迁移、图像生成、单样本统计 | 会去掉样本级对比信息，分类未必合适 |
| RMSNorm | Transformer/LLM，追求效率 | 没有 mean centering；和 LayerNorm 不总是等价 |

放置也要比较：

- **pre-norm vs post-norm**：Transformer 里影响训练稳定性；CNN 里影响残差路径。
- **融合前归一化还是融合后**：是候选，不是无条件正确；先看幅值/分布是否有意义，别把有用的尺度信息擦掉。
- **新分支的 BN**：看统计轴、每卡有效样本、空间相关性和领域偏移；可试 GroupNorm、SyncBN 或冻结统计量，但要单独对照。
- **推理一致性**：BatchNorm 默认 `eval()` 用 running stats，同一样本的输出不随 eval batch 组成改变；InstanceNorm/GroupNorm/LayerNorm 等按样本/组统计，行为不同；`track_running_stats=False` 是例外。冻结 affine 参数不等于冻结 running stats/buffers。

## 6. 初始化怎么选

初始化目标：前向不爆炸/不消失，反向有梯度，初始模型行为可解释。

- **Xavier/Glorot**：适合 tanh/线性，关注输入输出方差。
- **He/Kaiming**：ReLU 系列卷积/线性层的默认起点。
- **正交初始化**：RNN、深网络、需要保持范数时。
- **零初始化最后一层/门控**：让新分支初始为 identity，先不破坏父模型；但要区分参数化。`y=x+g·W·h` 中 `g=0,W≠0` 时首步 `dW=0`、`dg` 可非零；`W=0,g≠0` 时上游可能暂时为零；两者精确为零才会互锁。`g=sigmoid(a)` 时 `a=0` 对应 `g=0.5`，不是关闭。
- **预训练初始化**：强 baseline 首选；注意分类头、归一化统计、输入通道/尺度差异。
- **残差分支**：最后一层零初始化、缩放残差、LayerScale 都是让深网络可训的手段。

### 初始化的验收

- **step 0（仅函数保持接口）**：同一权重、同一 buffers、`eval()`、同一 RNG 下，关闭/零初始化分支的输出与父模型一致；残差/adapter 之外不强行要求 identity。
- **前向**：每层激活的均值/方差/范数不逐层爆炸或归零。
- **反向**：关键“解锁参数”（门控标量、最后一层、adapter）在预期窗口内有更新；不要求所有新参数首步非零。若出现双零互锁，用参数 delta/梯度反例定位。
- **训练后**：同一 checkpoint 上做 on/off 干预，估计该模块在当前模型中的贡献；这不是“回到父模型”，也不是净增益。

## 7. 通道、尺度与语义对齐

外来模块接不进去，通常不是“模块不行”，而是张量契约不对。

- **通道**：`1×1 conv`/linear 投影到目标通道；concat 后接融合层；add 要求通道相同。**通道数相等不等于语义轴相同**（NCHW/NHWC、token/空间维、类别维）。
- **空间尺度**：上采样/下采样/插值/池化/stride/dilation；记录 `align_corners`、padding、stride、patch center、坐标原点。同 H×W 仍可能因半像素/padding/RoI 产生错位。
- **几何对拍**：用 impulse/checkerboard、已知点/框/掩码做 `transform → inverse`；离散标签用最近邻等保类别方式，连续热图/流场/soft mask 按语义选插值。
- **感受野**：模块原本在哪个 stage、什么分辨率、多大感受野；换位置后语义可能变了。
- **语义**：backbone 浅层是纹理/边缘，深层是语义；把深层模块硬接到浅层，未必是同一件事。
- **归一化与激活**：融合前对齐分布是候选；注意 BN 的统计量来自哪个分辨率/batch。
- **mask/缺测**：通道 mask、padding、无效区域是否参与 loss/归一化；3D 的 spacing/orientation 是否一致；mask 插值是否产生非法类别。

对齐后先做 shape/数值断言，再训练；不要用“能跑”代替“语义对”。

## 8. 模型融合怎么融

融合的收益来自**单模型够强 + 错误足够不相关**，不是模型数量。

- **差异来源**：不同 seed、fold、架构、输入尺度、增强、snapshot、训练目标。
- **先看相关性**：同一模型附近多 seed 往往高度相关，简单平均收益有限。
- **权重怎么定**：validation/OOF 上选；不要在 test 上选融合权重。
- **融合方式**：简单平均 → 加权平均 → logit/概率平均 → stacking；stacking 必须用 out-of-fold 预测。
- **校准**：融合后置信度可能变差；分类看 ECE/阈值，检测看分数校准。
- **成本**：显存、延迟、吞吐是否可接受；用部署 batch/shape、warmup 后同步计时，报 p50/p95 和峰值显存。是否为 0.2 分翻倍由任务效用和用户阈值决定，不写通用禁令。
- **选择**：融合权重、成员数、是否加某个模型，都是模型选择；用 select 段，不用 test。

## 9. 外来模块怎么接：判断什么，不在这里排工序

模块效果不是一个孤立属性，而是**机制 × 位置 × 接口 × 数据/训练配方**。执行清单、位置选择和接线检查以 [组件工作流](component-integration.md) 为准；本节只保留训练诊断要问的问题：

- **位置**：模块在原生位置、bottleneck、decoder、skip、neck、head 前，哪一处匹配失败模式？候选按结构决定，不设固定个数。
- **接口**：通道/尺度/语义、mask、归一化、激活、初始化、梯度能否对齐？函数保持接口才要求 step 0 等价。
- **训练**：新模块的 lr/warmup/freeze、优化器成员、有效贡献、是否被后续层忽略。
- **对照**：同参数量 control、同 checkpoint on/off、独立 baseline、同主预算轴、多 seed；按当前替代解释选，不必每次全做。

### 三种比较，别混成一个

1. **step 0 等价**：同一权重、同一 buffers、`eval()`、同一 RNG，比较父模型与关闭/零初始化分支。只适用于函数保持接口。
2. **训练后 on/off**：同一 checkpoint 上关闭新模块，估计“当前模型里这条分支的贡献”。它不会恢复原始父模型，因为 backbone/BN 已共同适应；不能当净增益。
3. **独立训练 baseline**：同数据、同主预算轴、同评价器，从头训练匹配 baseline。净增益看这个，不看 on/off。

普通负结果可以限界记录后换方向；有增益再做机制消融，没增益先查证据，不把“没涨”自动外推成“模块家族无效”。

## 10. 对照组怎么设

按“要排除哪个替代解释”选对照，不要求每次全做：

- **baseline**：同数据、同 split、同主预算轴、同评价器、同阈值规则；独立训练。
- **step 0 等价**：仅函数保持接口；同权重/buffers/eval/RNG。
- **训练后 on/off**：同一 checkpoint 的干预，定位贡献；不等于净增益。
- **parameter-matched control**：参数量/计算量相近的普通模块，排除“只是变大了”。
- **position control**：同一模块换候选位置；不适用就说明，不强制 2–3 个。
- **no-op/random**：随机特征或恒等分支，排除“多了参数就会涨”的假象。
- **seed / unit control**：3 seeds 是起点，不是统计证明；报告配对差值、优化波动、按独立单位 bootstrap 的抽样误差。候选接近时可选更简单/更早模型，结论写“无法区分”。
- **budget control**：同主预算轴；其他轴记录。不要用调得更久的候选比 baseline。

只改一个科学变量；干扰变量（lr、wd、warmup、预算）两边对称重调；固定变量写进结论边界。

## 11. 从论文到模块的判断链

论文说“通用涨点”，是**有条件的证据**，不是无条件的定理。正确链条：

> 任务/评价器匹配 → 机制假设成立 → 原生位置可迁移 → 工程实现忠实 → 同主预算轴对照 → 结果可重复

任何一环不成立，都不能把“没涨”直接归因于“模块没用”。

- 工程不对：先修工程，再讨论 idea；必要时找用户讨论，不静默改实验。
- 工程对、逻辑对、仍不涨：记录边界条件（数据规模、分辨率、任务、预算、位置），这才是对论文主张的有效反驳/限定。
- 工程对、逻辑不对：改假设或换 idea，不要靠堆 trick 硬救。

## 12. 训练前的最小检查单

- [ ] 任务、评价器、数据单位、baseline 写清；
- [ ] 记忆探针达到预期下限；真实增强下有学习信号；
- [ ] train/val loss 口径可比；曲线只能支持有限判断，不排他；
- [ ] loss 与输出/标签匹配；完美预测下限、logits/概率、mask 都检查；
- [ ] lr/batch/schedule/AMP/grad clip 稳定；不是 NaN 堆里调结构；
- [ ] 归一化、初始化、通道/尺度对齐有断言；
- [ ] 改模块时：位置、融合、初始化、梯度、step 0/on-off、同参数量对照分清；
- [ ] 融合时：单模型够强、错误相关性、权重只在 select 段选；
- [ ] 主预算轴明确、右删失标注；3 seeds 起步，报告不确定性；pilot 与正式比较分开；
- [ ] 结论只写“有用/无用/有害/不可判”，并写边界。
