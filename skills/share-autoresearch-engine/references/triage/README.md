# 结果反直觉：先查实验本身，再判模块

条件：结果低于事先写下的"若改动有效至少应达到"的下限；方向与论文、强基线或本项目已有证据相反；或同一改动在不同划分/seed 上正负跳动。
不变量：在下表各层有证据之前，结论只能写"不可判"，不能写"模块无用"或"数据不适合"。
边界：明显的程序报错按普通调试处理；本页针对"能跑、不报错、但结论可疑"。

## 有序排查（每层不过就修，从该层重跑；不跳层）

| 层 | 查什么 | 怎样证明检查本身有效 | 工具 |
|---|---|---|---|
| 0 | 结论本身：从原始预测文件重算指标；被评模型的检查点哈希 | 用冻结父模型重算，应与登记分数逐位一致 | 项目评分脚本 |
| 1 | 评分器：真值对真值满分、空预测为零、小扰动不变、大扰动失败 | 由真值渲染输出再走解码与评分，应满分（证明解码无损） | 项目评价器 |
| 2 | 输入与标签对齐：真实训练批次叠图；标签处信号 vs 背景 | **反向对照**：行列互换/标签打乱后信号应消失；不消失说明检查看不见标签 | `alignment_probe.py`（mlgain 组件接入参考库，可选，本包未包含） |
| 3 | 增强同步：合成已知点/掩膜过同一套增强 | 故意只变换图像时必须报错（测试里留这个反例） | 同上 `augmentation_sync` |
| 4 | 损失与目标：初始损失量级、完美预测时的下限、logits/概率 | 软目标的 BCE 下限 > 0，不以"loss 减半"判断学会 | 手算一个 batch |
| 5 | 接线：第 0 步开/关等价、优化器成员无漏无重、新参数有更新、零初始化分支解锁 | 门控与最后一层同时为零时分支永远学不动（测试反例） | `module_probe.py`（mlgain 组件接入参考库，可选，本包未包含） |
| 6 | 小样本过拟合 | **按训练时的变换评估**：没用翻转训练就不能用多方向平均评分；样本内任务指标应接近满分 | `train_sanity_checks.py`（mlgain 组件接入参考库，可选，本包未包含） |
| 7 | 阳性对照：父模型复现冻结版本；同流水线训练一个已知好的模型达到其分数 | 两者都过才说明流水线能产出好结果 | 项目训练入口 |
| 8 | 选点：选中步、第一个可选验证点、新分支解锁时间、选中时有效贡献 | 选在第一个可选点或解锁前 → "未测" | [`selection_exposure_check.py`](../../scripts/selection_exposure_check.py)、[选择卫生](../selection-hygiene.md) |
| 9 | 模式与重载：eval 模式下 BN/dropout、严格重载后输出一致、EMA 与原始权重分清 | 新进程重载检查点重新预测，应与保存的预测一致 | `train_sanity_checks.py`（mlgain 组件接入参考库，可选，本包未包含） |
| 10 | 贡献：训练后强制关闭模块；有效贡献 RMS(Δ)/RMS(主路) | 关闭后分数整体平移时，用与阈值无关的指标或重选阈值后再比 | `module_probe.py`（mlgain 组件接入参考库，可选，本包未包含） |
| 11 | 容量与重调：同容量普通模块对照；两边对称重调干扰超参 | 对照与候选同预算、同 seed 配对 | [调参](../tuning/README.md)、受控比较（mlgain 组件接入参考库，可选，本包未包含） |

全部过了、重调后仍无增益，才可判"无用"；比父模型稳定更差才判"有害"。

## 把排查变成门禁

- 项目在 [项目合同](../workflow/project-contract.md) 第 6、7 节写下每层对应的命令；[`integration_gate.py`](../../scripts/integration_gate.py) 的 `"profile": "triage"` 会要求评分器自检、输入对齐、增强同步、按训练变换过拟合、阳性对照、选点检查都有结果（增强同步与阳性对照可写不适用理由）。
- 评审时区分"实现失败"（某层没过：修好再试）和"方向失败"（各层都过、对称重调后仍无益：放弃该方向），两者不混写（吸收自 RD-Agent，见 [上游卡片](../upstream/rd-agent.md)）。
- 小心检查本身写错：1号 R13 的过拟合检查先后用了"loss 减半"和"无翻转训练却用八方向评分"两个错误标准，都是靠追加探针发现的。每条检查都要有一个它必须报错的反例。
