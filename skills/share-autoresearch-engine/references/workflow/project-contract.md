# 项目级深度学习合同

条件：一个项目第一次做训练、调参、改结构、移植论文模块或模型比较；或已有合同与当前做法不符。
不变量：通用流程在本技能（[标准流程](standard-flow.md)），项目事实与项目规则在项目自己的合同文件里；全局规则只负责把人引到这里。

## 为什么是"项目长文 + AGENTS 一行指针"

- 深度学习的坑大多是项目特有的：坐标约定、评价器、划分单位、哪个检查点是父模型、哪些数据封存。这些写进全局规则会污染其他项目，写进技能又会过期。
- 项目 `AGENTS.md` 每轮都加载，按六合一约定保持短；长合同放项目文件，`AGENTS.md` 写一行"做深度学习工作前读 <合同路径>"，需要时才读全文。
- 合同由模板生成，章节固定，`dl_project_contract.py check` 能发现缺项，后续 AI 接手不靠记忆。

## 做法

1. 生成：`python3 ~/.claude/skills/share-autoresearch-engine/scripts/dl_project_contract.py init --project <项目根> [--path <相对路径>]`。默认写到 `_wiki-methodology/_wiki/_methods/dl-project-contract.md`（六合一项目）或 `docs/dl-project-contract.md`；已存在则拒绝覆盖。
2. 填写：按模板逐节写项目事实；不知道的写"待确认：…"并在 TOP 记一条，不编造。第 6 节的通过标准按本项目范式填写（读 [范式手册](paradigms/README.md) 第 7 节），确实不适用的检查写"不适用：理由"，不要为凑表伪造像素或坐标检查。
3. 指针：在项目 `AGENTS.md` 的项目规则里加一行（`init` 会打印建议文本；`--add-pointer` 可直接追加，已有同路径指针时不重复）。
4. 检查：`... check --project <项目根>`：章节齐全、无未填占位、以 `path:相对路径` 标记的项目文件存在、`AGENTS.md` 有指针。公式、命令与外部链接不按路径核验；绝对路径只提示、不判失败。返回码 0 通过，1 有缺项，2 参数错误。
5. 维护：流水线、评价器、划分、父模型或团队配置变化时更新对应章节，并在第 11 节追加"现象 → 原因 → 检查"。历史不在合同里堆叠，靠 Git。

## 边界

- 合同不是实验记录：结果、数字、进度写 TOP 与结果目录，合同只放规则与入口。
- 一个项目有多个独立子任务时，可以有多份合同（每份对应一个评价器与划分），`AGENTS.md` 分别指向。
- 合同的检查只验证"写全了、指得到"，不证明流水线正确；正确性靠第 6、7 节的实际运行结果。
