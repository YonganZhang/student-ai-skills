# 深度学习标准流程：从任务到可采纳的改动

适用条件：任何要训练、调参、改结构、移植论文模块或比较模型的深度学习任务。不同任务范式（视觉、时序、表格）在同一流程上替换具体内容，见 [范式手册](paradigms/README.md)。项目首次进入本流程时，按 [项目合同](project-contract.md) 把本页各阶段落成项目自己的长文规则。

本页回答两件事：**按什么顺序做**，**每一步交出什么才能进下一步**。具体做法链接到已有参考，不在此重复。

## 阶段与门槛

| 阶段 | 交出什么（门槛） | 详细做法 |
|---|---|---|
| S1 任务与指标 | 原生指标、聚合方式、匹配规则、阈值或解码规则写成合同；评价器实现入口 | [评测对齐](../evaluation-alignment.md) |
| S2 数据接口 | 数据合同（下文）+ 真实样本叠图；预处理统计量只来自训练子集 | [数据卫生](../data-hygiene.md)、[泄漏清单](../leakage-checklist.md) |
| S3 划分与选择 | fit / select / evaluate / test 四段、独立单位、数据种子；测试集开启规则 | [划分合同](../split-design-contract.md)、[选择卫生](../selection-hygiene.md) |
| S4 基线与阳性对照 | 强基线分数 + 一个"已知好"的参照能在本流水线复现其分数 | [迁移学习优先](../transfer-learning-first.md)、借 pipeline（mlgain 组件接入参考库，可选，本包未包含） |
| S5 流水线体检 | 评分器自检、叠图含反向对照、增强同步、按训练变换做记忆/学习探针；关键项通过再开实验 | [排错](../triage/README.md) |
| S6 结构判断与一次改一处 | 先写[结构判断](../architecture-judgment-gate.md)（可内联）；改动以插座接入，逐格故障检查（函数保持接口才要求第 0 步等价；否则查作者初始化、激活/更新窗口；优化器成员、有效贡献、选中步、严格重载、同 checkpoint on/off）无报警 | [结构判断门禁](../architecture-judgment-gate.md)、[组件工作流](../component-integration.md)、论文移植忠实性（mlgain 组件接入参考库，可选，本包未包含） |
| S7 调参 | 科学/干扰/固定变量分开；改结构后对两边对称重调干扰超参；搜索可续跑 | [调参](../tuning/README.md) |
| S8 比较与采纳 | 配对多 seed；与阈值无关的指标和工作点指标都报；同容量对照；结论为 有用/无用/有害/不可判 | 受控比较（mlgain 组件接入参考库，可选，本包未包含）、[稳定冠军](../stable-champion-protocol.md) |
| S9 溯源与归档 | 每个 run 有运行清单（代码含被忽略文件、数据、环境、seed、划分、检查点哈希）；结论带证据等级 | `scripts/run_manifest.py`、[证据链](../evidence-trail.md) |

跳阶段的代价：S5 没过就比较模块，得到的"无用"可能是流水线错误；S3 没定就调参，选择层会成为主噪声源。

## S6 前置：结构判断门禁

进入 S6 的**正式结构实验**前写清：失败模式、结构图、原生位置、机制假设、单轴实验、证伪条件；完整模板见 [结构判断](../architecture-judgment-gate.md)。
未写不进正式结构训练；有界 wiring/shape/固定少量 step 接线探针可先做（标 `probe`），不把 smoke 当证据；训练入口用 `../../scripts/structure_gate.py` 在首个 `optimizer.step()` 前校验 JSON 单与当前配置一致。没有能区分假设的对照，不把负结果写成“模块无效”。

位置优先于模块：先用同一模块比较能区分假设的候选位置（含原生位置；若只有原生位置，写明原因），再比较模块族。固定同一个外挂接口换模块，得到的负结果是相关的，不是多个独立失败。

同一接口连续负结果时，先审查接口和搜索空间，不直接外推“模块家族无效”。

## 接口设计（所有范式共用的五个合同）

写代码前先把这五个接口写成断言，代码按接口组织，不按"一个大脚本"组织。

1. **样本合同**：`sample_id`（独立单位可追溯）、输入张量的 shape / dtype / 轴含义 / 数值范围、标签编码（类别值、坐标约定 row/col 还是 x/y、半像素偏移、单位）、掩膜与缺测、预测时可见的字段。断言写在 Dataset 的 `__getitem__` 出口。
2. **变换合同**：几何变换对输入与标签同步；离散标签不插值；强度变换只作用于输入；验证/推理与训练的归一化来源一致或差异有记录。
3. **模型合同**：`forward(batch) -> 命名输出`；新模块经插座接入；函数保持接口才要求硬关闭/零初始化/step 0 等价，其他接口沿用作者初始化并检查激活与预期窗口内的更新；记录有效贡献。`state_dict` 严格重载后 eval 输出一致。
4. **损失与目标合同**：目标由标签确定性生成；完美预测时损失达到其下限（软目标下限 > 0）；logits/概率不混用；辅助损失的权重与起点量级有记录。
5. **评价合同**：原生评价器单独可调用、可自检；选择（checkpoint、阈值、解码）只用 select 段；评分只读预测文件与标签，不在训练进程里顺手改阈值。

训练循环只依赖这五个接口：`build_data(cfg) / build_model(cfg) / loss(outputs, targets) / evaluate(predictions, labels) / select(curve)`。换模块、换任务、换调参器时只替换对应实现。

## 每个 run 必须留下

配置（实际生效值）、运行清单、训练与验证曲线、选中步与理由、逐格故障检查结果、预测文件与回执、评分结果。缺一项就不能进入 S8 比较。

## 智能体团队怎么接

团队（分析员、结构/训练专家、检查员、结果分析员）只在 S6–S8 的"提什么改动、怎么解读"上出力；S1–S5 的合同与体检由执行者完成并冻结。每轮按 [多智能体协作](../multi-agent-protocol.md) 的假设台账记账，团队只看 select 段反馈。值不值得让团队做某个决策，先按 [职责与理想决策](../agent-value-oracle.md) 算天花板。
