# 软件骨架模块

用户已授权中文触发和设计任务按需使用。触发：设计软件骨架、设计架构骨架、搭建软件骨架、开启骨架模式、开启 Potato 模式；任务实际需要先确定模块边界、数据模型或接口结构时也匹配。不因“骨架”一词匹配论文、绘图或局部修复。

## 启用

1. 读取项目规则、确认目标项目目录。尚在讨论概念或没有具体软件项目时，只说明已配置入口，不往家目录或无关仓库安装。
2. 检查项目已有架构总控和同名目录；复用相同版本，保留本地改动，不覆盖冲突文件。已有明确任务授权覆盖此模块启用，无需再次请求安装许可。
3. 将 `../../templates/skills/dev-software-skeleton/` 内容复制到目标项目 `.agents/skills/dev-software-skeleton/` 与 `.claude/skills/dev-software-skeleton/`，将 `SKILL.md.template` 改为 `SKILL.md`，随包 UPSTREAM.json 的 local_paths 同步改名。不安装整个 pstack 或新增 MCP/plugin/hooks。
4. 在项目既有装备记录处（没有时用 `.agents/module-receipts/software-skeleton.json`）保存模块名、上游 commit、适配身份 `software-skeleton-v1`、安装路径和逐文件 SHA-256。固定项目版本，后续更新单独核对本地修改。
5. 检查两端 frontmatter、相对引用和实际宿主技能发现；需刷新/重启就报告。当前会话可读取安装后的 SKILL.md 按流程执行，但不能把文件存在声称为原生发现成功。

## 使用与维护

设计时读项目 skill；尚未完成发现刷新时，直接读取已安装文件执行，并明确发现状态。软件设计授权不等于自动实现授权，继续范围以用户请求为准。

更新前比较回执指纹，发现本地修改先保留并评估；回滚恢复上一个模块备份及回执，不回滚生成的业务产物。停用时移走项目入口并保留设计文件，不影响其他项目。
