# 会话复盘（retro）

触发：用户说"复盘 / retro / 这次哪里可以让下次更顺"。目标是改进 agent 的工作环境，不是评价这次写的代码。
输入：用户指定的会话，未指定就用当前会话；翻会话记录时只引用必要片段，凭证脱敏。

## 找改进点（只报真实发生过的）

| 类别 | 何时看 | 典型改法 |
|---|---|---|
| 导航 | 找文件或信息花了很久 | README、`_codemap.md`、AGENTS.md 加一行指针；把隐式的文件依赖写明 |
| 自动检查 | 犯了检查能抓住的错；或项目没有任何 pre-commit/CI 跑 lint、类型、测试 | 先读项目已有的检查命令和 CI，避免重造；没有任何检查机制、已有但没接上或悄悄失效、现有检查覆盖不到本次的机械错误，分别作为发现。固定语法、禁用 API、import 形状、文件位置这类机械问题优先用已有 lint/CI 做成确定性检查，判断类问题才写进审查规范 |
| 审查规范 | 审查环节漏了错误 | 判断类规范主要在审查阶段核验（审查仍按 share-code-review 追接口两侧与真实消费者），实现阶段照常遵守规范，只是不必常驻冗长的核对清单；补、删或澄清一条 |
| 常驻规则 | rules 或 AGENTS.md 很大 | 能变成检查或 skill reference 的移走，常驻只留边界与指针 |
| 工具开销 | 出现很贵的工具调用 | 换更窄的查询，给 CLI 加过滤或机器输出 |
| 无效指令 | 常驻文件冗长 | 删掉不改变默认行为的句子（见同目录 `mattpocock-writing-for-agents.md`） |
| 信息可达 | 关键信息 agent 拿不到 | 开发服务日志落盘、开放只读的第三方访问 |

## 输出
按严重度排序列候选：发生了什么（引用会话证据）→ 改哪个文件或加什么检查 → 成本。改全局 rules/skills、新增 hook 先经用户同意；项目内改动按项目规则处理。
