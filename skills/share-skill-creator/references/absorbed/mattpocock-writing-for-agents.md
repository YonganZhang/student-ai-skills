# 写给 agent 读的文档：措辞检查点

适用：写或改 skill 正文、rule、AGENTS.md，以及任何被指针引用的文档。结构（指针 + references、description 格式、行数目标）按 `../conventions.md`；本文件只补措辞。

## 指针
- description 和 rule 里的"详见 X"都是指针：措辞决定 agent 何时、多可靠地去读。必读材料读不到时先改指针措辞，仍不行再内联。
- 一个分支一个触发词，同义词合并；正文已经交代的身份信息不在指针里重复。

## 两种成本
- 上下文负担：常驻内容增加输入，实际计费受宿主和缓存影响。认知负担：用户要记住有哪些文档、何时用；只在需要人判断的地方让人记。
- 分层：每个分支都要的放正文，只有部分分支用到的推到独立文件。同一概念的定义、规则、例外放在同一标题下。

## 步骤与完成标准
- 每一步结尾写清"做到什么算完成"。标准含糊时 agent 会被后面的步骤吸引而提前收工：先把标准写准；仍然抢跑，才把后续步骤放到子 agent 或交接之后（同一上下文里拆段没有用）。
- 好标准可核对且穷尽："每个改动的模型都已说明"强于"列出改动"。

## 用词
- 选模型本来就懂的词当锚点（tracer bullet、变红、tight 回路），反复用同一个词，而不是反复解释同一句话；自造词要付定义成本。
- 优先正面写出目标行为，"不要做 X"会把 X 带进上下文。安全红线与 `conventions.md` 的绝对禁止条款照旧保留，最好同时写出该怎么做。

## 修剪
- 一个意思只在一处写。能从环境一查就知道的（脚本、配置、`--help`、目录结构）不抄，只写查不到的约定、理由和坑。
- 逐句问"删掉它行为会变吗"，不变就整句删；太弱的词（"认真点"）换成更强的词，不追加解释。
- 过时段落比缺段落更伤，改行为时同步删旧说法。
