# 冲突处理规则

## 冲突类型

### 1. 场景重叠（最常见）
外部 skill 的场景与现有 skill 部分重叠。

**处理**：合并到现有 skill，外部内容作为 reference 补充。不新建 skill。

### 2. 建议冲突
同一场景，外部 skill 和现有 skill 给出不同的建议/做法。

**处理**：
1. 不静默混合
2. 在目标 skill 的 `references/conflicts/` 下创建冲突记录文件
3. SKILL.md 索引表中标注 `[冲突待决]`
4. 展示两方内容给用户，等用户拍板
5. 用户选择后，胜出方合入正式 reference，冲突记录保留但标注 `[已解决]`

冲突记录格式：
```markdown
# 冲突：{场景名}

## 现有方案（来自 {existing_skill}）
{内容摘要}

## 外部方案（来自 {repo}/{path}）
{内容摘要}

## 差异点
- {具体差异1}
- {具体差异2}

## 解决状态
- [ ] 待用户决定
```

### 3. 质量差异
外部 skill 内容质量明显低于现有 skill。

**处理**：标记为 reject，记录原因。不合入低质量内容。

### 4. 粒度不匹配
外部 skill 太粗（一个 skill 覆盖多个场景）或太细（一个场景拆成多个 skill）。

**处理**：
- 太粗 → split，按场景拆分后分别合入对应现有 skill
- 太细 → 合并到一个现有 skill 的同一个 reference 文件

## 浓缩吸收原则（核心）

**AI 已有认知的内容不记解释，只记触发点。**

判断标准：
- 一提关键词（如 PICO）AI 就知道怎么做 → 只记关键词，不记定义
- AI 知道概念但实际工作中没执行过 → 记工作流检查点（"做 X 时别忘了 Y"）
- AI 完全不知道的具体参数/模板/API → 完整记录

浓缩格式：
```
## {场景名}
触发：{什么时候用}
要点：{关键词1} | {关键词2} | {关键词3}
检查：{容易遗漏的步骤}
```

一个 reference 文件不超过 30 行。超过说明没浓缩够。

## 优先级原则

1. **AI 已会的不吸收解释** — 只记触发点和检查点
2. **现有 skill 的结构和风格 > 外部 skill** — 永远适配到现有体系
3. **用户的判断 > 任何自动规则** — 有疑问时问用户
4. **少量高质量 > 大量低质量** — 宁可少吸收，不引入噪音
5. **可回滚 > 不可回滚** — 每步都有备份
