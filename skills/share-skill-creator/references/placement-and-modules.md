# 能力落位：全局、项目与可选模块

吸收 skill、仓库、方法或工具前先读本页。先判断用户要借鉴知识、复用代码，还是让 AI 执行工作流；普通库不因来自 GitHub 就包装成 skill。

## 三种选择

| 选择 | 条件 | 落点与行为 |
|---|---|---|
| 全局能力 | 跨项目临时调用有价值，或属于所有项目都需遵守的边界 | 工作流进共享 skill，规则只保留短边界；正文和参考按需读 |
| 项目专属能力 | 依赖某个项目的代码、数据、品牌、期刊要求或运行环境 | 项目 skill / 项目文档；不把项目事实写入全局 |
| 可选模块，按项目启用 | 能复用到多个同类项目，但完整流程、工具依赖或职责冲突需要项目隔离 | 全局只保留装备入口；模块配方不自动发现；启用后安装成项目 skill，固定版本 |

可选模块是一种分发与维护方式，不是第三种宿主加载作用域。模块安装到项目后，仍遵守项目技能的发现和按需读取机制。来源位置、发现范围、正文读取时机和更新策略分别判断。

## 决策与授权

个人全局技能过多会增加每次会话的候选清单；只在少数项目用到的能力优先放项目技能或按需模块，项目里反复用到、跨项目也有价值时再提升为个人全局技能。

1. 检查现有路由、真正消费者、触发频率证据和上游依赖。说明推荐选择及理由；未知频率写未知，不凭目录大小决定迁移。
2. 用户已指定范围或批准方案时直接执行；仅要求评估时给出具体建议。存在实质取舍时展示候选，不把三选一变成每次必答问卷。
3. 同职责总控明确选一个；工具型能力可以配合使用。低频但跨项目的读文件、演示制作等能力，不为减少一条描述而强迫逐项目安装。
4. 先复用 `share-project-provision` 的目录、模板、安装配方和 `UPSTREAM.json`，不为模块化新建包管理平台。只有实际重复操作才脚本化。

## 模块生命周期

- **入库**：登记仓库、不可变 commit、许可、适配点和依赖。模块源包放技能扫描范围之外；留在已有模板库时入口使用 `SKILL.md.template`，防止嵌套技能意外全局曝光。重包可只保存固定版本的安装配方，使用时获取对应源码。
- **启用**：解析精确目标项目，检查已有同职责技能及本地修改，预览将写入的路径。沿用当前授权；不覆盖既有文件或自动停用别人的技能。使用宿主当前支持的项目技能路径，并实际验证发现。
- **版本**：项目记录实际安装的来源 commit、适配身份、安装文件指纹和工具版本；源库的 `UPSTREAM.json` 不能代替项目安装记录。记录是安装回执，不复制项目任务状态。
- **更新**：上游巡检只发现变化。评估差异、验证后再更新模块库；项目升级另按当前授权执行。项目不软链到可变 `main/latest`，也不随全局模板升级。自家模块可更快晋级，但同样检查项目本地修改。
- **自动化**：skill、可执行工具、hook、扩展分别决定。先使用满足任务的最小组合；来源 commit 与工具二进制版本分别固定。不因安装 skill 顺带启用 hook/MCP/plugin。
- **检查**：项目内容与其声明安装版本比较；最新版本只作升级提示。报告修改、缺失和未知文件，不能把旧版本直接称为损坏，也不能把文件落盘称为宿主发现成功。
- **退出**：撤销模块入口及它注册的自动化；项目生成的代码、设计事实和研究材料保留。本地改动及旧安装按资产生命周期归档；共享缓存有其他消费者时保留。

## 验收

回放一个真实吸收请求和一个相邻负例；确认推荐范围、授权与按需读取正确。安装型模块另验证：项目可发现、其他项目不暴露、拒绝冲突不改原文件、指纹可检测本地变化、升级/回滚说明可执行。效果比较使用真实任务，静态路由检查不能当效果提升证据。

安装由 [项目装备入口](../../share-project-provision/SKILL.md) 执行；来源记录见 [upstream-tracking.md](upstream-tracking.md)。
