# 方法框架与技术路线图

明确要求“黑白技术路线图”或沿用该样式时，先走 [黑白技术路线图](../content-black-white-roadmap/SKILL.md)：DeepSeek 辅助、展开方法循环、图内只留业务内容，再按需调用本技能生成原生源图。

把方法画成短节点和有意义的连线，交付可编辑的 draw.io 原文件和清晰预览。
不是把参数表装进方框再用箭头串起来。

介绍、设计或优化项目方法论，需要讲清输入、模块、输出或接入关系时，默认采用[方法讲解图合同](references/method-framework.md)的简洁原生图式：白底、少量角色配色、短节点、带传递量的箭头，未确定的接入显式区分。单点释义、进度询问或不改变方法关系的小修改不强制成图。通常先交一张总图，细节另下沉；不把一种示例布局强加给所有方法，也不把方法沟通自动当作论文图候选选择。项目方法正文/证据的维护由 `project-top` 负责。

用户说“画个思维导图”“方法思维导图”或“技术流程图”，语境是方法步骤、模型接入、依赖或实现关系时，直接采用本技能的可编辑图式，不要求用户说规范名。仅整理知识主题/文章层级时按内容组织导图；明确要求可交互、折叠展开的HTML时另用交互网页导图工具（可选，本包未包含），不凭“思维导图”一个词自动改为网页。

## 边界

- 适用：技术路线、计算流程、输入输出依赖、原方法与改进方法的模块对照。
- 数据统计图交给科研绘图技能 `share-sci-plot`（可选，本包未包含）；交互式递归解释网页不由本技能接管。
- 项目进度甘特图、图片生成、神经网络张量架构图不由本技能接管。
- 默认保留已经批准的总图；新增细节用子流程图，不擅自改计算结果。
- 新 SCI 示意图（含图一）如已安装科研绘图技能 `share-sci-plot`（可选，本包未包含），先读其科研示意图候选合同；未安装时按本技能交付原生图。精确技术路线仍按本技能交付原生节点；新图按共享默认数量或用户指定数量探索不同可编辑布局，固定布局复刻与选后局部修改遵循共享例外；在同一科学语义下设计，真实节点、数据流和依赖关系保持一致，不为凑候选改计算过程。

## 工作流

1. 读论文原始方法、现有代码和已批准图，建立节点清单：名称、输入、输出、单位、来源、是否实际执行。
2. 区分外部已有数据、上游数据生产、当前计算、旁支结果。输入不能画成当前运行新算出的结果。
3. 从最终输出反查依赖，确定缺项；成图按输入到输出顺读。箭头必须能回答“传递了什么”。
4. 先画总图，再画模块详图。若比较方法，先完整还原原方法，再标继承、替换、新增、本地校准；概念对应线不冒充数据流。
5. 读取 [布局与实现](references/layout-and-tools.md)，用原生节点、分组和连接器生成未压缩 `.drawio`。长公式、参数定义和依据放配套说明，图中保留符号与短名称。
   通用生成、渲染和来源过期检查用 [method_diagram.py](references/method-framework.md#工具)：纯标准库生成原生图，按需用现有浏览器渲染；不要每个项目复制一套渲染器。已有批准图优先局部编辑。
6. 同级因素分别成节点，由虚线框归组。节点主文通常不超过两行；需要解释的内容下沉到说明或下一张详图。
7. 先固定语义和连线，再优化留白、间距、配色和路径。不为“高级”增加装饰，不靠整体缩字塞内容。
8. 用真实渲染器导出 SVG/PNG/PDF，打开每页检查；静态 XML 合法不等于图画对了。
9. 按 [验收](references/acceptance.md) 逐项检查，保存源图、预览、依据和检查记录。需要 Word 时再嵌图并检查分页。

## 验证入口

```bash
python3 <skill-dir>/scripts/validate_drawio.py <diagram.drawio>
python3 <skill-dir>/scripts/test_validator.py
```

验证器检查结构、页面和分组越界、悬空连线、重复 ID、嵌入表格/整图图片。
它不判断理论正确性，也不替代字体、遮挡、箭头走向的视觉检查。

## 不变量

- 原始方法、研究者新增假设、实现近似必须能区分；不能为贴合图形捏造机理。
- “全参数”意味着总图和详图及说明共同覆盖，不是一个节点塞入全部参数。
- 实线计算流、虚线对应关系等视觉语义在同一交付中固定，并在图注说明。
- 单位、归一化方向、分支汇合、共享输入及中间量都应有明确归属。
- 可编辑图中不能只有一张位图；总图结构不能是 HTML 表格。
- 外部仓库仅按需查阅，审查许可和依赖后才复制或执行；不自动安装不明 skill。
