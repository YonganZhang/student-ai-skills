# 布局与工具

## 布局语法

1. 使用固定网格，主流程从上到下或从左到右；同页避免方向反复。
2. 建议起点：20 px 网格、节点内边距 12 px、模块间隔 40–60 px。按最终印刷尺寸调整，不把这些数值当通用最优值。
3. 数据可用平行四边形，处理用矩形，终点用圆角矩形；尽量少用形状，语义一致比形状数量重要。
4. 六项并列指标是六个短节点及一个虚线父框，不是一格六条长句。组标题只描述共同概念。
5. 共享输入从一处接出；汇合前明确变量用途。旁支结果侧向输出，不能误画成下游必要前置条件。
6. 预留线槽。先用正交连接器，拥挤时设置端口和拐点；禁止穿字、穿无关节点、线头落在节点中心。
7. 多页之间使用模块编号和同名输入输出衔接。不要重复同一张图只换配色。
8. 用项目已批准色板；数据、计算、输出、替换关系各有少量稳定编码。黑白打印仍能靠线型和标题读懂。

## 原生实现

- 使用未压缩 mxfile / diagram / mxGraphModel / root；节点是 mxCell vertex，箭头是 mxCell edge。
- 组内子节点的 geometry 是相对父组坐标。编辑节点时箭头应保持 source/target 连接，而不是漂浮线段。
- 一页一个独立 XML 文档解码，避免多页重复 ID=0/1 在 mxCodec 中串页。
- 用 draw.io Desktop 官方导出优先；已有验证过的浏览器 mxGraph 渲染器也可复用。
- 精简 mxGraph 渲染器不一定支持 draw.io 所有形状。使用前检查 shape 和 perimeter；平行四边形边界需同时支持，不能只画轮廓。
- 几何理论图必须按真实几何关系画边，不用近似形状误代直角梯形等对象。
- 字体在导出环境必须实际安装；对每页检查 SVG 文本范围和实际截图。

## 工具选择依据

查阅日期：2026-09-09。下列是选择建议，不意味着均已安装或在所有任务验证。

- [draw.io 官方范例](https://github.com/jgraph/drawio-diagrams)：优先参考可编辑节点、连接器和分组；适合精确、可修订的技术图。
- [research-drawio-skill](https://github.com/QIANJINYDX/research-drawio-skill)：参考科研分区、路由和可编辑图策略。不把其图片生成步骤设为必选；参数图的正确性来自方法而非生成图片。
- [ELK.js](https://github.com/kieler/elkjs)：节点很多时可试自动分层布局。只用于初始位置，不能替代语义分组和人工视觉验收；未验证前不声称比现有布局更好。
- [draw.io 基础流程图](https://www.drawio.com/docs/getting-started/basic-flowchart/)：统一基础形状用法。

不必为了美化同时安装全部工具。优先延用已批准的原生绘图入口，真正出现拥挤和路由瓶颈再引入自动布局。
