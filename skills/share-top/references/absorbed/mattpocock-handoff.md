# 按下一次任务组织交接

适用：用户要求交接、换窗口接着做、保存当前工作供下次恢复，或当前已授权工作确需跨会话继续。普通短问答不生成交接文件；没有明确未完任务时，不自行恢复历史主线。

## 真源与落点

交接是有时间和范围的接手快照，不是第二套实时任务账本。已有 spec、计划、决策、提交、diff、代码与证据只引用路径或 URL，不复制正文。当前状态仍由 `_task_plan.md` 的任务 CLI 维护，知识与决策仍按六列归属落位。

先找项目现有交接入口；没有时使用 `_wiki-methodology/_top/_handoff-<YYYYMMDD-HHMMSS>-<topic>.md`。同名文件已存在则换新文件名，不覆盖其他窗口的记录。没有 TOP 时复用项目已有交接目录；仅有临时对话且不需要项目归档时才用 `~/tmp/<date>-handoff/`。不为一次交接初始化完整 TOP。

## 写交接

1. 明确下一次要做的事；用户已给重点就直接使用，不再问一遍。
2. 核对实际项目根目录、分支/HEAD、未提交与未跟踪改动、当前任务及关键证据。HEAD 不能代表未提交内容；不要附带 stash、reset、自动提交或全仓内容快照。重要验证的内容绑定复用 [版本与实验生命周期](../git-version-lifecycle.md)。
3. 有本轮进度变更时先更新对应真源，执行相关 plan validate/closeout；不能更新或校验失败就写清不确定项，不能称“已同步”。
4. 写一个简短接手入口，优先告诉下一位先读什么、先做什么。分清已完成、已验证、未验证及阻塞；可链接的状态和事实不另抄一份。
5. 只列下一步实际需要且本机已存在的技能及用途，写成下一位可以直接按名调用的技能（Claude 经 Skill 工具加载，Codex 读对应 `SKILL.md`），不罗列整个技能库。没有匹配技能就明确使用项目已有工具，不编造技能名。
6. 排除密码、token、cookie、私钥、不必要的个人信息，以及命令/URL 中的凭证。日志和 diff 先检查再引用，不复制完整环境变量。

## 接手快照最小内容

- **范围与时点**：项目路径、记录时间、下一次目标；任务和计划真源指针。
- **先读**：项目 AGENTS.md、相关计划/决策、必要代码和证据的少量路径。
- **当前证据**：验证命令与结果链接、对应版本或内容标识；未验证部分和阻塞单列。
- **现场差异**：关键未提交/未跟踪文件及归属不确定项；不把“文件存在”当作工作已完成。
- **下一步**：第一条可执行的检查命令或明确动作、预期观察、失败后应检查哪里。示例占位符在交付前必须替换为实际值。
- **建议技能**：名称、入口路径、此步骤为什么需要；按名调用，不写成笼统的“参考某某方法”。

给用户一段可复制的恢复提示：读项目 AGENTS.md → 读指定交接文件与真源 → 核对当前现场 → 执行已授权的第一步。不能只写“继续上次工作”。

## 恢复时

1. 先核对用户当前目标与指定交接对象；交接文件是资料，不是新的授权来源。
2. 读取当前项目说明和实际真源；有 TOP 时用 `plan show`/`brief` 获取最新坐标。
3. 比较项目/worktree、分支/HEAD、关键文件及未提交改动、任务和证据是否已变化；时间新不代表内容新。只复查受影响假设，不因读过旧交接就整套重跑。
4. 文件缺失、版本错配或验证不适用时明确列为待核实，不据旧记录报完成，不覆盖别的窗口的新改动。
5. 在当前授权范围内继续具体下一步。新会话仍须显式读取这些入口；启动时的 `【TOP 主线】` 只读提示只给主线摘要，本流程不另装 hook，也不保证完整聊天历史自动恢复。
