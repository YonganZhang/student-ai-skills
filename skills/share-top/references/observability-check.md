# 项目观测入口与证据导航

TOP 记录本项目“在哪里查、如何查、证据属于哪次运行”。通用排障与补充观测能力由开发工具箱技能 `dev-toolkit`（可选，本包未包含）维护；不在六合一复制一套通用技能。

## 何时更新

用户询问日志/训练指标/验收证据位置、需要交接已有观测入口，或本次工作实际改变了这些入口时，检查并更新对应导航。初始化项目、接手、切换模式或规模增长不要求扫描全仓、建观测系统或写 skip 日志。

## 登记什么

在项目已有 AGENTS、README、Wiki、实验说明或验收记录中选择现有归属；入口只放一处，其他位置链接它。按实际需要记录：

- 日志、stderr、指标、产物或 trace 的路径/查询命令，以及如何按运行 ID 或时间筛选；
- 对应代码版本、配置、数据或实验记录的关联方法；
- 已验证的用途和限制，例如日志保留期、采样、不覆盖的阶段；
- 长期任务的关键结论链接到原始证据，沿用 TOP 的按需记录规则。

没有新入口或可复用结论时不写新条目。没有 TOP 的项目沿用原有文档，不因此初始化六合一，也不为观测复制项目级技能或新增常驻规则。

## 需要排障或补能力时

已安装 `dev-toolkit`（可选，本包未包含）时读其相应分支：先使用已有记录；只有明确的证据缺口或用户建设需求才考虑补充能力。是否实施沿用任务授权，TOP 本身不依据代码规模或技术栈发出建设指令。
