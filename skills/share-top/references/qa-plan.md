# 问答式计划（`plan-format: qa`，2026-10-16 起的默认写法）

一个项目就是一串**问题**。人只读"问题 + 答案"就能看懂整个故事；AI 在每个问题下面有自己的**工作本**，记一步步的尝试、细节和笔记。研究会回头：做到后面发现前面错了、改参数重跑、论文写完又改主线——这些在工作本里用"来源/替代/作废"记清楚，在人那层只表现为"答案改过一次"或"⚠ 要重新确认"。

旧的目录格式（阶段 → 步骤）见 [plan-writing.md](plan-writing.md)，仍然能读能写；改成问答格式见文末「迁移」。

## 什么进计划

按目标归属和"下次接手要不要知道"判断，不按耗时：

1. **短的、碎的、跟长期目标无关**（上网查个东西、一次性小改、顺手修环境）→ **完全不进计划**。改了文件、提交了代码也不用记，不用解释。
2. **服务某个问题的实施细节** → 并进那个问题里已有的尝试；只有出现新结论、换路线、重要卡点、或下次接手需要知道的事，才 `plan note` 或新加一个尝试。
3. **有独立目标和验收、现有问题装不下** → 新开一个问题。另一个长期产品（例如给论文配套的网站平台）应该是它自己的项目，这里只留一句"论文用到它的什么"。

只做碎活的窗口可以根本没有计划（轻量模式）。

## 三层

| 层 | 文件 | 给谁 | 拥有什么 |
|---|---|---|---|
| 目录 | `_top/_task_plan.md` | 人；AI 的总入口 | 目标、问题的**顺序**、焦点、下一步。每个问题下面那句摘要是 CLI 从工作本生成的镜像，不要手改 |
| 工作本 | `_top/_questions/Q<n>.md`，一个问题一份 | AI 自己 | 问题、为什么问、怎样算答清、状态、答案修订、尝试、旧编号对照、笔记 |
| 证据 | `_logs/`、`_findings/`、`_decisions/`、Git、数据登记 | 追查 | 不变 |

连接只靠编号：问题 `Q4`、尝试 `Q4.3`。提交写 `Task: Q4.3`（只有一个尝试在进行时 git hook 自动加）；多个提交可以共用一个尝试。

## 版本与升级

根文件第二行的 `top-version` 是计划结构版本，只增不减；只有需要迁移的结构变化才升版，普通文案调整不升。`plan check` 会报：

- `TOP_VERSION_MISSING`：没有版本号。不能直接手补；先检查内容，`plan upgrade --apply` 只在没有硬错误时标记当前版本。
- `TOP_VERSION_OLD`：版本落后。`plan upgrade` 预览；有迁移器才 `--apply`。
- `TOP_VERSION_NEW`：计划来自更新的 skill。报错并拒绝写入，不降级；先更新 skill/CLI。

新项目模板、`plan init` 和 `plan rewrite` 自动写当前版本；`plan upgrade` 已是最新时不改文件。升级只处理结构，不替用户改项目内容。

## 写法

**给人看的**（`ask` / `answer` / `reopen` / `goal` 写入，CLI 查长度和行话，只提醒不拒绝）：
- **问题**：一句能回答的话，≤20 字，例如"新结构有用吗？""论文写完了吗？"。按"有没有独立的验收和答案"来拆，**不按尝试次数拆**——一个问题下面试 50 次很正常。
- **怎样算答清**：一句验收，例如"多种子盲测稳定高于基线""全文数字与最新结果一致，作者审过"。
- **答案**：结论在前（是/不是、有用/没用、说不清），≤40 字；一个关键数字要带单位或比较对象（"只比原来高 0.3 个百分点"，不是"只剩 0.3"）。必须带证据（`--ev` 尝试编号、`finding:…`、路径或提交）。
- **目标**：一两句大白话，做完是什么样。
- 都不写文件名、路径、编号、参数；专业名词一句最多一个。

**给 AI 自己的**（尝试、笔记）：可以技术化，必要的参数和数字照写。尝试写"做什么"，做完补"→ 结果"（一句话）。细节、路径、实验编号写进工作本的 `## 笔记`，或用 `plan note` 进日志。

## 非线性：回头、重跑、推翻

规则：**做完的结果不改写**（done/cancelled 的结果和证据不再改）；回头就新加一个尝试并写关系；撤回答案立即生效。

| 情况 | 怎么记 |
|---|---|
| 发现前面的结果错了 | `plan reopen Q2 "数据切分有泄漏" --because Q3.11 --invalid Q2.4`：Q2 的答案立刻撤回（目录显示 ↺"旧答已撤回…正在复核"），Q2.4 标作废 |
| 改参数把一段重跑一遍 | `plan add "改切分参数重跑" --to Q2 --from Q2.4..Q2.5 --because Q3.11`（区间在写入时展开成明确编号） |
| 新结果确认取代旧结果 | `plan done Q2.6 "数据集 v2，无泄漏" --ev … --supersedes Q2.4`（只有做完并确认后才写替代） |
| 别的问题依赖了被撤回的结论 | `reopen` 会列出答案引用了它的问题；需要重看就 `plan flag Q5 "依赖的 Q3 被撤回" --because Q3`（⚠，答案不撤回），复核完 `plan flag Q5 --clear` 或重新 `plan answer` |
| 论文写完又要改主线 | 论文是一个问题（"论文写完了吗？"）。上游结论变了就 flag 它，改稿是它下面的新尝试，改完重新 answer |
| 长时间训练 | 尝试保持进行中，`plan note "运行中，完成后看验证集 F1" --on Q3.7`，不为等待新造步骤 |
| 已答清的问题还想补做验证 | `plan add "补一个消融" --to Q4` 再 `plan start`：问题回到"在弄"，答案保留；结论变了就重新 `answer`，发现错了就 `reopen` |

例子（中间态与完成后，人看到的）：

```
↺ 数据切分对吗？    旧答已撤回：数据切分有泄漏；正在复核
↺ 新结构有用吗？    旧答已撤回：依赖的数据切分有泄漏；正在复核
▶ 论文写完了吗？    初稿已写完 · ⚠ 要重新确认：依赖的结论被撤回

✔ 数据切分对吗？    原来有泄漏，已改正（改过 1 次）
✔ 新结构有用吗？    没用：修正泄漏后只高 0.3 个百分点（改过 1 次）
▶ 论文写完了吗？    初稿已按新结果更新
```

## 现在与下一步：显式，不猜

- **焦点**（正在弄清哪个问题）：`plan start Q5.9` 自动把焦点设到 Q5；`plan focus Q6` 手动换。焦点问题答清或放弃后焦点清空，用 `plan focus` 选下一个。
- **下一步**：`plan focus Q5 --next Q5.10` 或 `--next "一句话"`，`--after` 表示做完当前这步后。被 start 或 done 后自动清掉。没设时只从焦点问题里取最早的待办（标"候选"），再没有就写"待选定"。
- **需要你**：`plan block Q4.3 "等你定期刊" --you` 或 `plan wait Q4 "等作者回邮件" --you`。只有真有事时才出现在首屏（及接入的计划看板）上。主线在等、AI 在做旁支时照实显示，不拿旁支冒充主线。

## 命令

`plan help` 一屏速查。常用：

```bash
plan                              # 目标、正在弄清、当前判断、正在做、下一步、需要你、问答目录
plan Q4 [全部]                    # 一个问题的工作本（全部 = 全部尝试和笔记）
plan P5.38                        # 迁移前的旧编号去了哪里
plan ask "问题？" --done-when "怎样算答清" [--why "为什么问"] [--after Q3]
plan answer Q4 "答案" --ev <证据> [--because …] [--keep-open]       # 默认答完关闭问题
plan reopen Q4 "原因" [--because Q3.11] [--invalid Q4.8,Q4.9]       # 撤回答案
plan flag Q5 "要重新确认什么" [--because Q3] | plan flag Q5 --clear
plan wait Q4 "等谁/要什么" [--you] | plan wait Q4 --clear
plan add "做什么" [--to Q4] [--gate "怎样算做完"] [--from Q2.4..Q2.6] [--because Q3.11]
plan start Q4.3 | plan done Q4.3 "结果" --ev <证据> [--supersedes Q4.1] [--commit]
plan block Q4.3 "原因" [--you] | plan cancel Q4.3 "原因" | plan reopen Q4.3
plan focus Q5 [--next Q5.10 | --next "一句话"] [--after]
plan note "一句话" [--on Q4.3|Q4] [--fail|--learn]                    # 进日志
plan rename Q4 "新问法" | plan move Q4 --after Q2 | plan drop Q4 "原因" | plan goal "…"
plan check | plan upgrade [--apply] | plan init "目标"（新项目） | plan rewrite 草稿.md --to qa [--apply]（迁移）
```

- 编号形状决定对象：`Q4` 是问题，`Q4.3` 是尝试（`reopen`、`rename` 两种都接）。
- 改别的项目要用 `-p <路径|窗口号>`。看板等外部写入方带 `--expect <revision>`，计划被别处改过就报冲突。
- 工作本的 `## 为什么问`、`## 怎样算答清`、`## 笔记` 可以直接编辑（编辑前先重读）；`## 答案`、`## 尝试`、头部注释和目录文件只经命令改。

## 文件长什么样

目录 `_task_plan.md`（摘要由 CLI 生成）：

```markdown
# <项目> — 计划
<!-- plan-format: qa · top-version=1 · focus=Q5 · next=Q5.10 · next_when=now -->

## 目标

<一两句大白话>

## 现在

<!-- plan 命令自动生成，不要手改 -->
- 正在弄清：论文写完了吗？
- 当前判断：初稿已写完 · ⚠ 要重新确认：依赖的结论被撤回
- 正在做：按新结果改结论段和图 3
- 下一步：给作者审
- 需要你：定投稿期刊

## 问答

<!-- 问题的顺序由这里决定；摘要由 plan 命令从 _questions/ 生成，不要手改 -->

### 数据切分对吗？ ✔ <!-- id=Q2 -->
答：原来有泄漏，已改正（改过 1 次）
```

工作本 `_questions/Q5.md`：

```markdown
# Q5 论文写完了吗？
<!-- id=Q5 · state=active · answer=r1 · review=依赖的结论被撤回 · review_by=Q3 · created=2026-10-12 -->

## 为什么问

<和目标的关系>

## 怎样算答清

全文图表数字与最新结果一致，作者审过

## 答案

<!-- plan 命令维护；只追加 -->
- r1 初稿已写完 <!-- date=2026-10-12 · ev=Q5.4 · status=current -->

## 尝试

<!-- plan 命令维护；做完的结果不改写 -->
- [x] Q5.4 写英文初稿 → 初稿完成 <!-- ev=paper/draft/v1 -->
- [ ] Q5.9 按新结果改结论段和图 3 <!-- state=in_progress · because=Q3.12 -->

## 旧编号

<!-- 迁移生成：旧 ID → 新 ID；“历史”表示没有新对应 -->
- P5.* → Q5

## 笔记

参数、路径、实验编号、疑点。plan 命令写入时原样保留这一节（它必须是最后一节）。
```

问题状态：○ 未开始 / ▶ 在弄 / ⏸ 等待 / ✔ 已答清 / ↺ 答案撤回正在复核 / ✕ 不弄了；⚠ 要重新确认单独显示。尝试状态沿用 pending / in_progress / blocked / done / cancelled。

## 读写一致性

- 写操作拿项目锁（放在 `~/.cache/top-plan-locks/`，不进仓库），锁内重读，先写工作本（真源）、再写目录（镜像）、最后写日志；一次改动若让计划多出错误就整个拒绝。中途崩溃时：摘要过期、或新问题没进目录顺序，下一次写入会补上；焦点改动可能丢，`plan focus` 重设即可。
- `## 笔记` 必须是工作本的最后一节；头部注释里不认识的键、标题和第一节之间的文字、根文件格式标记里多出的内容，都会让写入被拒（`QA_UNKNOWN`），免得悄悄丢掉。
- 有进行中的尝试时，`answer` 不能直接关闭问题（先 done/cancel，或 `--keep-open`）；焦点问题关闭或放弃时，焦点和它的下一步一起清掉。
- 读操作永远从工作本算，不写盘。目录摘要被手改或上次写入没走完时，`plan check` 报 `QA_MIRROR_STALE`，下一次任何写入自动重建。
- 工作本里有读不懂的行或多出来的 `## 小节`，写入会拒绝（避免丢内容）：把自由内容挪进 `## 笔记`。
- 旧的写命令（阶段、insert、replan、archive……）和 `sixone-cli.py plan add/edit/…` 对问答计划一律拒绝。

## 迁移：旧计划改写成问答格式

1. **读全**：`plan`、`plan 全部`、计划原文、`_plan_details.md`、最近的 findings 和日志，弄清项目到现在回答过哪些问题。
2. **归并成问题**：一个阶段不一定就是一个问题——大阶段可以拆，小阶段可以并。做完的阶段写成"问题 + 答案"（负结果照写：`不能：四种办法都没通过`），保留 3–5 条关键尝试（`做了什么 → 结果`，带原证据）。跑题的历史（例如在论文项目里搭网站）要么另开问题，要么标"历史"，不要塞进论文问题。
3. **只留还有效的待办**，写进它所属问题的尝试里。
4. **每个旧编号都要有对照**：写进某个问题的 `## 旧编号`，`- P4.3 → Q4.2`；一整段用 `- P5.* → Q5`；没有新对应写 `→ 历史`。包括已完成、已取消、已归档的。旧提交不改写，`plan P5.38` 能查到去处；别的窗口还拿旧编号写入（`plan done P5.38 …`）会被拒绝，并告诉它新编号。
5. **细节**：`_plan_details.md` 里对应的技术细节搬进各问题工作本的 `## 笔记`。
6. **草稿**：写到 `_tmp/plan-draft-qa.md`。开头是目录部分，之后每个问题一块，以 `# Q<n> 问题` 开头、写法同工作本，块的顺序就是问题顺序：

   ```markdown
   # <项目> — 计划
   <!-- plan-format: qa · top-version=1 · focus=Q5 -->

   ## 目标

   <一两句>

   # Q1 旧论文的结果可信吗？
   <!-- id=Q1 · state=closed · answer=r1 -->
   ## 怎样算答清
   …
   ## 答案
   - r1 不可信：和教学演示数据一模一样 <!-- date=2026-10-10 · ev=Q1.2 · status=current -->
   ## 尝试
   - [x] Q1.2 追查结果来源 → 与教学演示数据逐字节相同 <!-- ev=finding:… -->
   ## 旧编号
   - P1.* → Q1
   ## 笔记
   …

   # Q2 …
   ```

   还开着、要用户拍板或动手的尝试写成 `- [ ] Q5.7 请作者定期刊 <!-- state=blocked · who=you · reason=等你定期刊 -->`；整个问题在等外部时，问题头写 `state=waiting · wait=等谁/要什么`。

7. **预览**：`plan rewrite _tmp/plan-draft-qa.md --to qa`。必须没有错误（`QA_ALIAS_MISSING` 表示旧编号没对照）；旧计划里没完成的任务若在新计划里没有开着的去处，会列在 `dropped_open`，逐条核对。
8. **替换**：加 `--apply`（确认放弃那些未完成任务再加 `--accept-dropped`）。旧目录、细节文章、归档快照存进 `_logs/plan-history/<时间>-before-qa/`；工作本先就位，目录最后写（这一步才切换格式）。回滚 = 把快照里的文件拷回原位并删掉 `_questions/`。
9. **收尾**：`plan`、`plan check` 核对；只看目标和问答目录，要能讲清来龙去脉。把 `_top/` 一起提交。

## 为什么这样设计

- planning-with-files 的 `task_plan.md` 把"关键问题"放在最后一节；研究项目真正的骨架就是这些问题，所以提到最前面。它的计划、发现、进度三件套收进每个问题的工作本。
- GSD 的经验："现状是摘要不是档案"——目录只放问题和一句答案，过程进工作本和日志。
- ADR 决策日志：答案带修订，被替代或撤回只标状态不删除，编号不复用。
- Shape Up：不显示完成百分比，因为研究做着做着待办会变多。
- 2026-10 的问题：计划被当成 AI 的工单账本（一个请求一步，某阶段膨胀到 40 步、24 步跑题），"下一步"是机械推出来的空话，人看不出要自己做什么。所以：短碎任务不进计划、下一步显式、答案效力和工作状态分开、收尾提醒不再催记账。
