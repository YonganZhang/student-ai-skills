# 六合一架构 · 理念(Philosophy)

> 这是六合一架构的**为什么**,不是怎么做(来由见 `changelog.md`)。
> 任何改动六合一 / 加 CLI/API 工具,先回到这份理念对齐。AI 写得跟它冲突就是错的。

## 0. 一句话

**六合一 = 给 AI 的操作系统 + 人机协作流程。** 这是一个 **AI 主导、人掌舵**的项目范式:
人掌舵(定方向、定靶子、提方法论),AI 干细节;但 AI **没有全局记忆、读不完代码**(几十万到上百万行,每次重读=烧钱烧时间)。
解法:**读一次 → 沉淀成文档 → 下次 / 下个 AI / 下个对话直接读文档**,而不是重读代码。
六块里 **五块给 AI 自己用**(让它知道何时做什么、何时看文档、文档没有就扫代码再沉淀回去),**一块给人看**。

> **“六”只有一套定义**:Wiki、Top、Tests、Code(含 CodeBook)、Lifecycle、Whole Picture,真源与边界见 [canonical-six-columns.md](canonical-six-columns.md)。下面各小节按这六列讲“为什么”;“唯一真源”不是第七列,而是贯穿六列的不变量。
> **最小可行版本**只要求 `AGENTS.md` + `_task_plan.md`(坐标+当前任务)+ `_logs/`;其余列是可选模块,真需要时才启用。

## 1. 六列各自的"为什么"

### Top(列 2)· 计划主线
大平台有 1-2-3-...-N 步。服务器断电、换对话、AI 东改一下西改一下碎片化修 bug → **主线丢了**。
TOP 是主线:我做到第几步、下一步是什么。防"重进来不知道自己干到哪"。

### Code(列 4)· CodeBook(原名 CodeMap — 改名,理念升级)

> **2026-09-24 更新**:CodeBook 已退役。实测多数节点盖章过期、很少被读;代码一块改为 CodeGraph(结构,实时、零维护)+ `_codemap.md`(一页纸用途与入口)+ 决策记忆(理由,`record for-file`)。下文保留为设计来由;现行定义以 [canonical-six-columns.md](canonical-six-columns.md) 为准。
**它不是代码图谱,是"用户视角、自顶而下的代码文档 / 用户手册"。** 管两件事:
1. **用户手册**:从**用户视角自顶而下**写。例:考试成绩系统 → 用户看到的实体 = 学生登录 / 卷子评分 / 教师登录 / 成绩管理 …… 每个系统下又有后端 / 算法流程(语文+数学+英语=总分)。
   - 实体即目录 → **分级目录**(L1/L2/L3/L4,或 Book1/Book2,或 CodeBook1/CodeBook2),**渐进式披露 + 目录的目录(TOC-of-TOC)**。
   - AI 一看就知道:有哪些系统 → 子模块 → 子函数 → 该函数的测试案例,**一下找得到**,且都记录成册。
   - 目的:减 token、**逼复用别重造轮子**(已有 skill/CLI/API 还想造重复功能 = 错;复用靠"先看这本册子")。
2. **Pipeline(固化的线)**:一根线穿很多扣子,扣子=函数(可能 70 个都是)。固化 = 有一个 `main` 入口,**一键跑整条线**。下次只跑这个 main 就复现流程,**不缺函数、不跑错、AI 不偷懒**。工作流的数量/形状由人在开发中自定,不固定。

**CodeBook vs 代码图谱(codegraph)的分界**(关键):
- 代码图谱:`init` 即完工、全自动,但**粗糙、弱、无人参与,AI 在里面写的内容很垃圾**;给"代码长什么样"(调用图/找函数/死代码)的**机器粗图**。
- CodeBook:**有人参与、用户视角、自顶而下、高价值**;给"这软件有什么、怎么用、怎么跑"的**人/AI 共写的手册**。
- 二者**互补不替代**:**靠 CodeBook 寻路(navigate by book),靠代码图谱核实(verify by graph)**。

### Tests(列 3)· 固化测试(自我提升的靶子)
怎么让 AI 提升自己?**给它设好具体靶子**(例如项目自己定下、有依据的召回率或预测准确率目标),固化成测试案例,让它**自己不断挑战自己**。
含 **自驱动监测架构**:AI **一边模拟人操作软件**(如自驱动浏览器把多次点击的前端流程录成视频)、**一边在后台记接口 + 中间变量**(供 debug 溯源)、**边做边自检**(做完再自检,甚至边做边检)→ 自己发现问题。
🔴 **每个项目的监测架构都不一样,是人现提的**(一开始什么都没有)。所以框架只给**通用外壳**,内容每项目自填。

### Wiki(列 1)· 方法论(专家知识库)
专家领域里刁钻的东西(例如某个领域指数的定义、怎么算成分数、各分项怎么合成)——**只能给 AI 装一个 Wiki 知识库**(Karpathy 式)。
人写给 AI 看 / 人引导 AI 写给自己看;来自参考书籍、概念、文献,**抽象成方法论**。
目的:**极大提升 AI 对专业领域的理解,让它写代码时具备我要的专家能力**。
具体怎么拆词条、怎么摄入/查询/体检,见 `references/wiki-writing-method.md`(这里只讲为什么)。

### Lifecycle(列 5)与唯一真源(贯穿六列的不变量)
Lifecycle 管数据资产、临时物和归档落点(可选的 data registry + `_tmp/_sandbox/_legacy`)。
每个重要的**代码 / 数据 / 算法 / pipeline / 抽象概念**都只有**一个源头**;别处用 markdown 链接指过去。
改源头 → **处处瞬间同步**。不只工程层,**也含抽象层概念**。

### Whole Picture(列 6)· 总览网页(唯一给人看的)
一个网页直接展示给人:这项目有什么内容、有什么价值。它是派生视图,不属于 TOP 必需部分,只在用户明确要网页时生成。

## 2. CLI/core helper 的理念边界(从讨论里抽出的硬判据)

- **CLI/core helper 只做 Read 干不了的三类**:① **跨多文件算出一个有界摘要**(status/pipeline 视图),② **判账本可不可信**(doctor 闸门),③ **路由到对的扫描工具**(代码图谱/LSP/语义)。
- 🔴 **纯"读一份文档"的不包工具** —— 直接 `Read` 即可,包了只是省一步 Read,性价比低。
- CLI 返回 **答案 + 源头相对路径**;**改/读仍走正常文件操作**(AI 拿路径自己 Read/Edit)。CLI 不替代文件访问,只做"算答案 + 指源头 + 设闸门"。

## 3. 让 AI 真正用起来(生死线)的理念

工具/文档,**AI 不主动调 = 死的**。靠两个机制兜底,把对"一条它早忘的外部死规矩"的依赖压到最低:
1. **冷启动主动握手**:每个新对话/换项目,AI 第一动作 = 跑 `sixone-cli.py plan show`(“我在哪”的唯一入口),**验证它还记不记得主线**。(原 SessionStart 整份 brief 注入已退役;现在只有只读的 1~3 行 `【TOP 主线】` 启动提示,提醒有主线,细节仍由 AI 主动跑 `plan show`。)
2. **提示长在脚本返回里(`next_hint`)**:"写新代码前先查复用 / 干完活回写沉淀" 这类**何时用什么**的提示,**写进脚本输出的 `next_hint`**,在那个松散时刻自然点着 AI —— 跑完一个脚本,输出推下一步。
- **`next_hint` = 自驱链的核心**:除启动时一条只读主线提示外没有自动注入、没有 MCP,**全靠"跑一个 CLI→输出推下一步"的自驱链**接力。诚实讲:规则比 hook 弱(会被跳过),自驱链是主要兜底,不是免费等价。
- 真实生命周期是**混乱的**(有时加模块、有时嵌 GitHub 项目、有时加新模型),**没有一条完整生命周期可套**。真正要保证的不是"按时刻走流程",而是:**写代码前该先看六合一 / 写完后该回写六合一 / 新对话进来要先确认它记得六合一**。

## 4. 第一次就做对 > 事后多道检查(2026-09-24 精简)

实测:计划被当日记写到几百 KB、检查器堆到 8 个以上、一次普通改动要 18~20 步收尾,而活跃项目约一半的检查长期报警无人理。检查不产生质量,**开工时写清验收 + 完成时一次证据验证**才产生质量。因此:

- 保留便宜且有效的:任务上的 `gate`(开工写清验收)、`plan complete` 必附证据、计划写入的并发保护、计划格式与体积校验。
- 收尾压到 4 步:`git status` → 只在改了入口/数据时更新登记 → `plan complete --evidence --commit` → 回复里说明。
- 事后 lint 门(top-lint、finding-doctor、topic-closeout、top-gate、tidy 等)降为可选工具,不再是流程要求。
- 没有结构化任务的计划是轻量模式,工具不对它提要求。

## 5. 一句话收束
六合一让"AI 主导、人掌舵"的项目,从**每次失忆重来**变成**持续积累**:
AI 靠 TOP 知道主线、靠 CodeBook 复用不重造、靠固化 pipeline 跑不错、靠测试靶子自我提升、靠 Wiki 写出专家级、靠唯一真源不漂移、靠总览网页让人掌控。
CLI/core helper 是这套操作系统的"系统调用层":只暴露 Read 干不了的(算/判/路由),用冷启动握手点着它,用工具返回里的提示领着 AI 走。
